## Goal
A statement saved as an old Excel workbook (.xls, BIFF8 inside an OLE compound file) is read like an .xlsx file: the import wizard gets the rows of the first statement sheet and continues with the Columns step. Today every .xls file stops at "This is an old Excel file (.xls). Save it as .xlsx or CSV and try again." Citadele's internet bank exports statements as .xls (owner's sample, 2026-10-17), so the owner cannot import his main bank at all.

## Notes
Facts from the owner's sample (`Statement-Citadele-01.10.2026-17.10.2026.xls`, 43 008 bytes, never committed: it holds real names, IBANs and a personal code), checked by the planner with a throwaway parser on 2026-10-17:
- OLE compound file version 3 (512-byte sectors, mini-stream cutoff 4096). Streams: `Workbook` (32 835 bytes), `\x05SummaryInformation`, `\x05DocumentSummaryInformation`.
- BIFF8 (BOF version 0x0600), CODEPAGE 1200, one sheet named "Statement". 876 records. Record types present: SST (0x00FC) with CONTINUE (0x003C), LABELSST (0x00FD, 395), RK (0x027E, 71), NUMBER (0x0203, 8), XF (0x00E0), FORMAT (0x041E), BOUNDSHEET (0x0085), DIMENSIONS, ROW, COLINFO, STYLE. No MULRK, LABEL, FORMULA, BLANK or MERGEDCELLS in this file.
- Dates of transactions are text cells "01.10.2026"; the two period cells in row 2 are number cells with format `dd\.mm\.yyyy`. Amounts are RK/NUMBER cells (-8.8, 1140.41, 0).
- Expected rows (0-based): 0 `Konts | XXXXXXX`; 1 `No | <date> | līdz | <date>`; 2 `'' x4 | Sākuma atlikums: | 75.31`; 3 the header; 4-74 the 71 transactions; 75-79 footer lines (`Beigu atlikums:`, `Debeta apgrozījums:`, `Kredīta apgrozījums:`, `Komisiju summa`, `Kopējā izejošo maksājumu summa bez komisijām`) in column 4 with the number in column 5.
- Text cells keep their line breaks ("28/09/2026 490847******4322 MCC-5814 REF: 817028\nLIDO ORIGO RIGA LV 54958376"); C-089 needs them, so do not collapse whitespace in the reader.

New module `src/import/xls.js`, export `readXls(input)` with the same contract as `readXlsx` (`{ ok: true, rows: string[][] } | { ok: false, reason }`, rows trimmed of trailing empty cells, empty rows dropped, cells as strings):
1. Compound file: header (sector shift, mini sector shift, FAT sector count, first directory sector, mini cutoff, first mini-FAT sector, DIFAT array of 109 plus DIFAT chain sectors), FAT, directory entries (UTF-16 names), streams of at least 4096 bytes from the FAT chain, smaller streams from the mini stream (root entry chain + mini-FAT). Guard every chain against loops and out-of-range sectors (DAMAGED message).
2. Stream `Workbook` (or `Book`). A directory entry `EncryptedPackage` → the existing PROTECTED message ("This workbook is password protected. Remove the password and try again."). A FILEPASS record (0x002F) in the globals → the same message. BOF version other than 0x0600 (BIFF5/Excel 95 and older) → "This Excel file is too old to read. Open it in Excel and save it as .xlsx." 
3. Globals: SST + CONTINUE (strings split across CONTINUE records restart with a one-byte flags field; rich-text runs and extended data are skipped), FORMAT, XF (format index at offset 2), BOUNDSHEET (offset, hidden state, name), DATEMODE (0x0022, 1904 system), CODEPAGE for 8-bit LABEL text (1200 = UTF-16; otherwise decode compressed text as latin1, which is what BIFF8 compressed strings are).
4. Sheet choice as `readXlsx` does: the first visible sheet (of the first 10) with at least 3 rows and a date-like cell, else the first visible sheet, else the first sheet.
5. Cells: LABELSST, LABEL (0x0204), RK (0x027E), MULRK (0x00BD), NUMBER (0x0203), FORMULA (0x0006: cached number, or the following STRING record 0x0207 for a string result, boolean, error), BOOLERR (0x0205), BLANK/MULBLANK ignored. Numbers whose XF format is a date (`isDateFormatCode` on custom formats, built-in ids 14-22 and 45-47) become `excelSerialToDate(value, date1904)`; other numbers `plainNumber(String(value))`.
6. Limits as xlsx.js: at most 16 384 columns and 1 048 576 rows; the file-size limit is already in `readStatementFile` (10 MB).

Wizard: in `readStatementFile`, OLE bytes (`isOldExcel`) go to `readXls`, ZIP bytes to `readXlsx`; the result is `{ ok: true, kind: 'table', format: 'xls', rows, delimiter: '', encoding: '' }`. Add 'xls' to `TABULAR_FORMATS` and to FORMATS in types.js.

Tests (new file test/importXls.test.js):
1. A fixture made with LibreOffice from made-up data in the same shape as the owner's file: `test/fixtures/xls/citadele-like.xls`. Build it once with `soffice --headless --convert-to xls` from a CSV written to a temporary folder (column A imported as text so the dates stay text, as in the bank's file; amounts as numbers). Rows: `Konts;XXXXXXX`, `No;01.10.2026;līdz;17.10.2026`, `;;;;Sākuma atlikums:;75.31`, the header, then at least 8 transactions with multi-line details cells, for example `01.10.2026;PIRKUMS;"28/09/2026 400000******0000 MCC-5814 REF: 100001` + newline + `KAFEJNICA PARAUGS RIGA LV 10000001";;ET00000000000A;-8.8`, a salary `05.10.2026;IENĀKOŠAIS EKS MAKSĀJUMS;"Darba algas izmaksa` + newline + `PARAUGS SIA 40000000000 HABALV22 LV00HABA0000000000001` + newline + `Maksātāja reference: NOTPROVIDED";2026100500000001;FT00000000000B;1140.41`, and the footer lines with `Beigu atlikums:` etc. Assert: `readXls` ok; the header row is index 3 and equals the six column names; the first transaction's details cell contains a line break; amounts read "-8.8" and "1140.41"; Latvian letters (ā, ē, ī, ļ, š, ž) are intact. Commit the .xls fixture only, not the CSV, and no data from the owner's file.
2. Synthetic records built in the test (a small CFB writer in the test file): an SST string split across a CONTINUE record with the flags byte changing from compressed to UTF-16; MULRK; FORMULA with a STRING record; BOOLERR; a number with a date format → 'YYYY-MM-DD'; a workbook smaller than 4096 bytes (mini stream).
3. Refusals: FILEPASS → the password message; BOF 0x0500 → the too-old message; truncated or looping FAT → the damaged message; a non-OLE input → the not-Excel message.
4. `readStatementFile` with a `File`-like object holding the fixture returns format 'xls' and the same rows (the function is exported; build the input with `new Blob([bytes])` and a `name`).

Format references (public specifications, not checked against Excel itself by the planner): [MS-CFB] Compound File Binary format and [MS-XLS] Excel Binary File Format, sections on SST/CONTINUE, RK, MULRK, FORMULA/STRING.
