## Goal
Before the user taps Add category, a line under the form lists which existing category limits change and from what to what; the confirmation toast says how many limits changed.

## Acceptance
- `node --test test/categoryAddPreview.test.js` exits 0
- `npm test` exits 0
- Manual (design-review): Add category form with the notice (Flexible chosen, three limits change), with "No limit" chosen (no notice), and with a Fixed share, at 390, 768 and 1280 px, light and dark; the notice wraps without overflow; owner checks
- Manual (owner): on a fresh plan with budget 1000, choose Flexible in Add category; the notice names the changed limits (from about 333 to 250 each); switch to No limit and the notice disappears; add the category and the Month limits match the notice

## Do not touch
- SCHEMA_VERSION and MIGRATIONS
- `resolvePlan`, `syncCategoryPlanFields`, `canSetPinned` and everything else in src/budget.js except the one new export
- The rules for what a flexible, pinned or no-limit category receives
- existing test files
- Limit for `src/budget.js`: one new pure exported function, `previewAddCategory`.

## Notes
Source: C3 F11 (screenshots c3-25-extreme-month.png vs c3-14-money-month.png): adding a 5th category with the default Flexible share lowered every flexible limit from EUR 333.33 to EUR 250.00 and "Necessary expenses over by" went from 309.07 to 392.40, with no notice. Line numbers are from `main-work` at 05d1355; verify before editing.

`src/budget.js`: add `export function previewAddCategory(categories, monthlyBudgetCents, candidate)` next to `resolvePlan` (:69-123). `candidate` is `{ pinned, percent, limitMode, limitCents }`. It must not mutate its input: `resolvePlan` calls `syncCategoryPlanFields` (:67-69), which writes `percent` and `limitCents` into the categories it is given, so work on `JSON.parse(JSON.stringify(categories))` (the repo's clone idiom, backup.js:38-40). Steps: `before = resolvePlan(clone, budget)`; `after = resolvePlan([...clone2, { id: '__new__', name: '', system: false, subcategories: [], ...candidate }], budget)`; return an array `{ id, name, beforeCents, afterCents }` for every entry that exists in both, is not `noLimit` in either, and has `beforeCents !== afterCents`. Budget 0 gives an empty array (all limits are 0).

`src/views/settings/categories.js` `renderAddCategory` (:452-502): add `const notice = element('p', 'muted category-add-notice'); notice.setAttribute('role', 'status');` below the kind choice and above the Add button, and a local `refreshNotice()` that builds the candidate from `addDraft`:
- kind `flexible`: `{ pinned: false, percent: 0, limitMode: 'percent', limitCents: 0 }`
- kind `none`: `{ pinned: false, percent: 0, limitMode: 'none', limitCents: 0 }` (no notice)
- kind `pinned`: percent unit: `parsePercent(addDraft.amount)`; euro unit: `percentFromEuroCents(parseAmount(addDraft.amount), budget)`; if the amount does not parse, show no notice.
Call `refreshNotice()` on render and from the `onInput` callback that `buildLimitAmountField` already accepts (:469-477, currently only clears the error). The kind radios re-render the form (`renderKindChoice`, :429-436), so the notice refreshes there.

Text (exact): when the array is empty, the notice is empty and hidden. Otherwise `This changes the limit of N categories this month: A €333.33 → €250.00, B €333.33 → €250.00, C €333.34 → €250.00.` (`1 category` for N = 1; list at most three, then ` and K more`; amounts with `formatEuro`). In `addCategory` (:146-239) compute the same array before pushing the new category and change the toast to `Category added. Limits changed for N categories.` when N is greater than 0, otherwise keep `Category added`.

Tests, new `test/categoryAddPreview.test.js` with `defaultData()` (three flexible categories Necessary, Random, Others; Subscriptions is No limit; Savings is pinned at 0%; Uncategorised is a system category) and `monthlyBudgetCents: 100000`: a flexible candidate returns exactly the three flexible categories with `afterCents === 25000` each and `beforeCents` equal to `resolvePlan(...).entries[i].limitCents` for them; a `none` candidate returns `[]`; a pinned candidate of 20 percent returns the same three with after-limits summing to 80000; budget 0 returns `[]`; the input `categories` deep-equals a copy taken before the call.
Not decided: making No limit the default share for new categories (C3 F11 suggestion). This card only adds the notice; see the open decisions in `_index.md`.
