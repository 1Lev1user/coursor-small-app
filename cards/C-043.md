## Goal
A new category is created with no limit, in both places that create one (Settings > Categories and limits > Add category, and the quick "new category" in Add expense), so no other limit changes (owner decision 16). When the user deliberately picks Flexible or Fixed in the Add category form, a line under the form lists which other limits change and from what to what, and the confirmation toast says how many changed, so a limit never changes silently.

## Acceptance
- `node --test test/categoryAddPreview.test.js` exits 0
- `npm test` exits 0
- Manual (design-review): the Add category form with No limit selected (default, no notice), with Flexible (three limits change, notice shown) and with a Fixed share, at 390, 768 and 1280 px, light and dark; the notice wraps without overflow; owner checks
- Manual (owner): on a fresh plan with budget 1000, open Add category: No limit is already chosen; add "Gifts": every Month limit is unchanged and the toast says `Category added`. Add another with Flexible chosen: the notice first names the changed limits (from about 333 to 250 each); after Add the Month limits match it and the toast says how many changed. In Add expense, create a category from the quick panel: no other limit moves

## Notes
Source: owner decision 16; C3 F11 (screenshots c3-25-extreme-month.png vs c3-14-money-month.png): adding a 5th category with the default Flexible share lowered every flexible limit from EUR 333.33 to EUR 250.00 and "Necessary expenses over by" went from 309.07 to 392.40, with no notice. Line numbers were re-checked on `main-work` at 6788db8; verify before editing.

1. Default is No limit. `src/budget.js`: `export function newNoLimitCategory(id, name)` returns `{ id, name, pinned: false, percent: 0, limitMode: 'none', limitCents: 0, system: false, subcategories: [] }`. `add.js` `createFlexibleCategory` (:184-201) becomes `createNoLimitCategory` and builds its category with that function (`createId('cat')` as today); the push, `syncCategoryPlanFields` and `refreshCurrentMonthPlan` calls stay. `categories.js`: `export const DEFAULT_NEW_CATEGORY_KIND = 'none'`; use it for `addDraft.kind` (:40-46) and for the reset after a successful add (in `addCategory`, :232, `addDraft.kind = 'flexible'` today); in `renderKindChoice` (:409-449) list `No limit` first, then `Flexible`, then `Fixed`; replace the hint under No limit (:442-448) by `No limit: no other limit changes. Spending still counts and shows as % of your budget.`
2. Notice for the choices that do move limits. `src/budget.js`: add `export function previewAddCategory(categories, monthlyBudgetCents, candidate)` next to `resolvePlan` (:69-123). `candidate` is `{ pinned, percent, limitMode, limitCents }`. It must not mutate its input: `resolvePlan` calls `syncCategoryPlanFields` (:45-67), which writes `percent` and `limitCents` into the categories it is given, so work on `JSON.parse(JSON.stringify(categories))` (the repo's clone idiom, backup.js:38-40). Steps: `before = resolvePlan(clone, budget)`; `after = resolvePlan([...clone2, { id: '__new__', name: '', system: false, subcategories: [], ...candidate }], budget)`; return an array `{ id, name, beforeCents, afterCents }` for every entry that exists in both, is not `noLimit` in either, and has `beforeCents !== afterCents`. Budget 0 gives an empty array (all limits are 0). A `none` candidate always gives an empty array.
3. `src/views/settings/categories.js` `renderAddCategory` (:452-502): add `const notice = element('p', 'muted category-add-notice'); notice.setAttribute('role', 'status');` below the kind choice and above the Add button, and a local `refreshNotice()` that builds the candidate from `addDraft`:
   - kind `flexible`: `{ pinned: false, percent: 0, limitMode: 'percent', limitCents: 0 }`
   - kind `none`: no notice (nothing changes)
   - kind `pinned`: percent unit: `parsePercent(addDraft.amount)`; euro unit: `percentFromEuroCents(parseAmount(addDraft.amount), budget)`; if the amount does not parse, show no notice.
   Call `refreshNotice()` on render and from the `onInput` callback that `buildLimitAmountField` already accepts (:469-477, currently only clears the error). The kind radios re-render the form (`renderKindChoice`), so the notice refreshes there.
4. Text (exact): when the array is empty, the notice is empty and hidden. Otherwise `This changes the limit of N categories this month: A €333.33 → €250.00, B €333.33 → €250.00, C €333.34 → €250.00.` (`1 category` for N = 1; list at most three, then ` and K more`; amounts with `formatEuro`). In `addCategory` (:146-239) compute the same array before pushing the new category and change the toast to `Category added. Limits changed for N categories.` when N is greater than 0, otherwise keep `Category added`.
