## Goal
A file whose amounts are unsigned and whose direction is written as "+/-", "OUT/IN", "Izdevumi/Ienākumi", or as a suffix like "12,50DR", is read with the right money direction. A direction column holding a word the app does not know no longer turns unsigned rows into income silently: those rows are listed as skipped.

## Notes
Source: D-bank.md problems 2 and 18 (VERIFIED), problem 2 is independently confirmed in D-bank-verify.md item 2 (probes c2.mjs, c2b.mjs; the confirmation also holds when the user maps the direction column by hand); the "12,50DR" suffix gap (problem 18) was found by D-bank only.

Cause 1: `directionOfValue` (text.js:293) uses the fixed tables `OUT_VALUES` / `IN_VALUES` (text.js:285-286). Any other value returns null, and `rowsToStatement` (text.js:819-826) then falls back to the amount sign, so a positive unsigned amount becomes 'in'. Add (compared after `stripDiacritics`, upper case): out: OUT, '-', IZDEVUMI, IZMAKSA, EXPENSE, РАСХОД; in: IN, '+', IENAKUMI (Ienākumi), IEMAKSA, INCOME, ПРИХОД. Add header keywords 'zime', 'sign' to `KEYWORDS.direction` (text.js:255). Content detection of an unnamed direction column (text.js:448-458) then finds a '+'/'-' column by itself.

Cause 2: in `rowsToStatement`, when `columns.direction >= 0`, the cell is non-empty and `directionOfValue` returns null: if the parsed amount is negative the row is 'out' (the sign is explicit); otherwise skip the row with reason 'unknown direction' (loud instead of silent). An empty direction cell keeps today's sign fallback. Add `'unknown direction': 'Direction not recognised'` to `SKIP_REASONS` (src/views/import.js:46-50).

Cause 3: `parseAmountWith` (text.js:634) only reads a D/C mark after whitespace (`/\s+(DR|CR|D|C|K)$/i`), so "12,50DR" loses the mark (the letters are stripped at text.js:658) and a debit becomes money in. Allow an optional space but require a digit directly before the mark, for example `/(?<=\d)\s*(DR|CR|D|C|K)$/i`. TRAP: "12,50 USD" and "12,50 CAD" end in D; they must stay plain amounts (the currency strip at text.js:639 handles them), so a bare `\s*` without the digit guard is wrong.

The vocabulary, the digit-guarded suffix regex `/(?<=\d)\s*(DR|CR|D|C|K)$/i` and the unknown-direction skip were prototyped by the planner on a copy of text.js: all 67 tests of importText.test.js pass and cases 1-6 below give the stated results.

2. Same with header `Veids` and values `Izdevumi` / `Ienākumi`; same with values `OUT` / `IN` (header `Direction`).
3. `Date;Description;Amount;Direction`, three rows with amount `10,00` and direction `-`, `+`, `-` gives out, in, out (before: in, in, in).
4. Controls that must not change: `D,K,D` and `DEBIT,CREDIT,DEBIT` give out, in, out.
5. Direction column set by hand (pass `columns.direction: 3` in the layout; the guess leaves it at -1 for unknown words) with value `WEIRD`: positive amount row is skipped with reason 'unknown direction'; row with amount `-10,00` is 'out' 1000; empty direction cell with `10,00` is 'in'.
6. `parseAmountWith('12,50DR', ',')` is -1250 and `parseAmountWith('12,50CR', ',')` is 1250; `parseAmountWith('12,50 USD', ',')` and `parseAmountWith('12,50 CAD', ',')` are 1250.
7. A Revolut-shaped header (`Type,Product,Started Date,Description,Amount,Currency` with CARD_PAYMENT / TOPUP values) still gives direction -1.
