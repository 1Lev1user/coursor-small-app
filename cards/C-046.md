## Goal
Quick-add templates, which pile up forever today, get the Settings group "Quick add" (the slot C-041 leaves between Subscriptions and Goals) where each one can be renamed, given a new amount, or deleted.

## Acceptance
- `node --test test/templatesSettings.test.js` exits 0
- `node --test test/serviceWorker.test.js` exits 0
- `npm test` exits 0
- Manual (design-review): the Quick add group with three templates, one in edit mode, and one delete confirmation, at 390, 768 and 1280 px, light and dark; tap targets at least 44 px (after C-072 the Edit and Delete chips may be smaller boxes with a 44 px tap area); owner checks
- Manual (owner): save two templates from Add expense, open Settings > Quick add, rename one and change its amount, delete the other; Home > Quick add shows the change after a reload; entries added earlier are unchanged

## Do not touch
- SCHEMA_VERSION and MIGRATIONS
- `addTemplate`, `deleteTemplate`, `templateToExpense` behaviour (test/templates.test.js stays green unchanged)
- The Add expense form and the Home Quick add buttons (add.js)
- existing test files
- Limit for `src/views/settings/shared.js`: new fields in `state` and their reset in `closeTransientUi` only.
- `SETTINGS_GROUPS` and the page rendering in src/views/more.js: C-041 already holds the `templates` group in the right place; this card only fills the slot.
- Limit for `src/views/more.js`: one import, one new entry in `SECTION_RENDERERS` (`'more-templates': renderTemplatesSection`), one new case in `groupSummary`.
- Limit for `sw.js`: one new line in `CORE_ASSETS` for the new module.

`src/templates.js`: add `export function updateTemplate(data, id, patch)` with `patch = { name?, amountCents? }`. Merge into the existing record, validate the merged `{ name, amountCents }` with the existing private `validateTemplate` (:7-20: trimmed name 1-40 characters, positive integer cents), return `{ ok: true, template }` or `{ ok: false, reason }` (`Template does not exist.` for an unknown id), and change nothing when validation fails. Category and note are not editable here; the Settings text says: `To change the category, delete the template and save a new one from Add expense.`

New `src/views/settings/templates.js`, modelled on the Subscriptions section (src/views/settings/subscriptions.js:280-438), exporting `renderTemplatesSection(ctx)`: a `section.card.stack` with id `more-templates`, `h2.section-title` `Quick add`, a muted line `Templates are saved from Add expense with "Save as template".`, then one `div.entry-item` per template showing name, the amount with `formatEuro`, and the category name (`data.categories`, fall back to `Uncategorised`), with `Edit` and `Delete` buttons (`btn btn-ghost` and `btn btn-ghost-danger`, helpers from ./shared.js). Edit opens an inline form (`inline-form`) with Name and Amount (EUR), Save and Cancel; errors inline through `buildField`, `setError`, using `parseAmount` and the reasons from `updateTemplate`. Delete opens `renderConfirm('Delete <name>? Entries you already added stay.', ...)` (the red `Delete` button appears only inside this confirm step). Success: `persist(ctx)` then `ctx.toast('Template updated')` / `ctx.toast('Template deleted')`. Empty state: `No templates yet.`
`shared.js` `state` gets `editTemplateId`, `confirmTemplateId`, `templateEditDraft`, `templateEditError` (all null/empty), reset in `closeTransientUi` (:45-71).
