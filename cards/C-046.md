## Goal
Quick-add templates, which pile up forever today, get a Settings group where each one can be renamed, given a new amount, or deleted.

## Acceptance
- `node --test test/templatesSettings.test.js` exits 0
- `node --test test/serviceWorker.test.js` exits 0
- `npm test` exits 0
- Manual (design-review): the Quick add group with three templates, one in edit mode, and one delete confirmation, at 390, 768 and 1280 px, light and dark; buttons at least 44 px high; owner checks
- Manual (owner): save two templates from Add expense, open Settings > Quick add, rename one and change its amount, delete the other; Home > Quick add shows the change after a reload; entries added earlier are unchanged

## Do not touch
- SCHEMA_VERSION and MIGRATIONS
- `addTemplate`, `deleteTemplate`, `templateToExpense` behaviour (test/templates.test.js stays green unchanged)
- The Add expense form and the Home Quick add buttons (add.js)
- existing test files
- Limit for `src/views/settings/shared.js`: new fields in `state` and their reset in `closeTransientUi` only.
- Limit for `src/views/more.js`: one new entry in `SETTINGS_GROUPS`, one new case in `groupSummary`, one new render call.
- Limit for `sw.js`: one new line in `CORE_ASSETS` for the new module.

## Notes
Source: A gap 4 and section 4.2 item 14; C2 2.8 ("There is no UI anywhere to edit, rename, re-price or delete a template", screenshot c2-42). `deleteTemplate` exists (src/templates.js:54-65) and is tested (test/templates.test.js:30) but no view imports it. The Home list has no cap (add.js:607-628). Line numbers are from `main-work` at 05d1355; verify before editing. Needs C-041 for the group list.

`src/templates.js`: add `export function updateTemplate(data, id, patch)` with `patch = { name?, amountCents? }`. Merge into the existing record, validate the merged `{ name, amountCents }` with the existing private `validateTemplate` (:7-20: trimmed name 1-40 characters, positive integer cents), return `{ ok: true, template }` or `{ ok: false, reason }` (`Template does not exist.` for an unknown id), and change nothing when validation fails. Category and note are not editable here; the Settings text says: `To change the category, delete the template and save a new one from Add expense.`

New `src/views/settings/templates.js`, modelled on the Subscriptions section (src/views/settings/subscriptions.js:280-438), exporting `renderTemplatesSection(ctx)`: a `section.card.stack` with id `more-templates`, `h2.section-title` `Quick add`, a muted line `Templates are saved from Add expense with "Save as template".`, then one `div.entry-item` per template showing name, the amount with `formatEuro`, and the category name (`data.categories`, fall back to `Uncategorised`), with `Edit` and `Delete` buttons (`btn btn-ghost` and `btn btn-ghost-danger`, helpers from ./shared.js). Edit opens an inline form (`inline-form`) with Name and Amount (EUR), Save and Cancel; errors inline through `buildField`, `setError`, using `parseAmount` and the reasons from `updateTemplate`. Delete opens `renderConfirm('Delete <name>? Entries you already added stay.', ...)`. Success: `persist(ctx)` then `ctx.toast('Template updated')` / `ctx.toast('Template deleted')`. Empty state: `No templates yet.`
`shared.js` `state` gets `editTemplateId`, `confirmTemplateId`, `templateEditDraft`, `templateEditError` (all null/empty), reset in `closeTransientUi` (:45-71).
`more.js`: add `{ id: 'templates', title: 'Quick add', sectionIds: ['more-templates'] }` to `SETTINGS_GROUPS` between `subscriptions` and `goals`, render the section in that group, and a `groupSummary` case `3 templates` (`1 template`, `None yet`). The new section's own `h2` is handled by the same heading rule as the other single-section groups (C-041).
`sw.js`: add `'./src/views/settings/templates.js'` to `CORE_ASSETS` (test/serviceWorker.test.js fails otherwise).

Tests, new `test/templatesSettings.test.js`: `updateTemplate` renames and re-prices (trimmed name, new cents), refuses an empty name, a 41-character name, `0` and `1.5` cents without changing the record, returns the unknown-id reason; `groupSummary('templates', data)` for 0, 1, 3 templates (import `groupSummary` from `../src/views/more.js`); `SETTINGS_GROUPS` lists `templates` after `subscriptions` and before `goals`.
