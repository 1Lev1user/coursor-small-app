## Goal
Single version source: npm version updates sw.js.

## Acceptance
- `node --test test/versionSync.test.js` exits 0
- `node --test test/versionSync.test.js 2>&1 | grep -E '^# pass ([2-9]|[1-9][0-9])'` exits 0
- `node -e "process.exit(/sync-version/.test(require('./package.json').scripts.version || '') ? 0 : 1)"` exits 0
- `npm test` exits 0

## Do not touch
- the VERSION value in sw.js
- the version value in package.json
- test/serviceWorker.test.js
- Limit for `package.json`: scripts.version only.
- Limit for `README.md`: Development 'Releasing' line only.

## Notes
The script reads the package.json version from the root (env VERSION_ROOT overrides it, like KIT_ROOT in scripts/check-kit.mjs:6), replaces `const VERSION = '...';` (sw.js:6), exits 1 with a message if that line is missing, and prints the new value. package.json scripts.version = 'node scripts/sync-version.mjs && git add sw.js'; npm runs the 'version' script after bumping and before the commit (npm docs for `npm version`), so `npm version 2.1.0` changes both files in one commit. Tests copy package.json and sw.js into a mkdtemp folder and run execFileSync(process.execPath, ['scripts/sync-version.mjs'], {env: {...process.env, VERSION_ROOT}}): version 9.9.9 ends up in sw.js; a second run changes nothing; a missing VERSION line gives a non-zero exit. test/serviceWorker.test.js:54 stays as the guard. The planner updates the release line in AGENTS.md afterwards.
