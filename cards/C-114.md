## Goal
Money now does not follow the bank: an import adds entries but never compares with the bank's balance (owner, 2026-10-18). After this card the import's last screen compares the statement's closing balance (C-113) with the app's money on the same date and offers to align them with one entry, the way Settings > Check against bank already does. When Money now is not set up yet, it offers the statement balance as the start.

## Notes
- Add `alignToBank(data, cents, dateISO, now)` in src/balance.js: like `checkAgainstBank`, but compares with `balanceAt(data, dateISO)` and dates the "Bank difference" entry on `dateISO`; returns the same shape. It refuses when `dateISO` is before the setup date or after today. Share the entry-building code with `checkAgainstBank` instead of copying it.
- Add `startMoneyFromBank(data, cents, dateISO)`: when `balanceStart` is null, set the anchor date to `dateISO` and the cents so that `balanceAt(data, dateISO) === cents`. Refuses when Money now is already set.
- Done screen, when the statement has a closing balance:
  - Money now set, statement date on or after the setup date: "Bank balance on 17 Oct: €429.15. My Expenses on that day: €X." When equal: "Matches the bank." When different: buttons "Align with the bank" (adds the entry; toast "Added a €D bank difference on 17 Oct") and "Not now".
  - Money now set, statement date before the setup date: "Bank balance on 17 Oct: €429.15. Money now starts on <date>, so this statement is not compared." No button.
  - Money now not set: "Use €429.15 from the statement as your money on 17 Oct?" buttons "Use it" and "Not now".
- The Bank difference entry gets the import's id in a new optional field (for example `alignedBy: importId`) so that undoing the import removes it too; `normaliseEntry` must keep the field (check model.js; it is outside allowed_paths, so if a change there is needed the planner amends the card). No schema change.
- Tests: equal balances (no entry), a positive and a negative difference (entry kind, amount, date, note), statement before the setup date (refused), not set up (start from bank, then balanceAt equals the bank on that date and Money now today follows the later entries), undo removes the Bank difference entry, `checkAgainstBank` unchanged.
