## Notes
Follow-up from the C-007 review (PR #11, finding 1). `state` in src/views/settings/shared.js:11-42 has `confirmDeletePreUpdate` but not `confirmRestorePreUpdate`, and closeTransientUi() (shared.js:44-69) resets only the delete flag, so the Restore confirm can stay open while another confirm opens. Add `confirmRestorePreUpdate: false` to `state` and reset it in closeTransientUi next to confirmDeletePreUpdate. The new test imports `state` and `closeTransientUi` from shared.js, sets both flags true, calls closeTransientUi and asserts both are false (check that shared.js imports without a DOM; if it does not, test only what it can and report). In backup.js the pre-update hint still says to download the copy and restore it with Import backup (around line 253); change it to point to the Restore pre-update copy button. Verify line numbers against main before editing.
