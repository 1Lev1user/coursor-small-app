## Goal
Card payments carry the merchant category code (MCC) the card network assigns: 5411 for a supermarket, 5812 for a restaurant, 4121 for a taxi. When no saved rule matches a row, the Categorise step pre-selects the category the MCC points to, so a first import of a month of card payments needs far fewer taps. The person still sees and can change every suggestion; nothing is saved as a rule unless they tick Remember.

- not mapped on purpose: airlines 3000-3350 and 4511, hotels 3501-3999 and 7011, 5734/5818 software and digital goods, 7999 recreation, 5994 newsstands, 6010-6012 cash and financial institutions, 4829 money transfers.

`defaultDecisions` (core.js ~379): when no rule matched, the row is money out and `subcategoryForMcc(row.mcc)` names a subcategory that still exists in `data.categories` (find the category whose `subcategories` holds that id), use that categoryId and subcategoryId instead of `UNCATEGORISED_ID` and ''. A matching saved rule always wins. A deleted or renamed-away default subcategory → no suggestion. Money-in rows are unchanged.

Tests (new file test/importMcc.test.js): each group maps one sample code; an unmapped code and '' give ''; `defaultDecisions` with a Rimi-like row (mcc 5411) and default categories → groceries; the same with groceries deleted → UNCATEGORISED_ID; a saved rule for the same row wins over the MCC; a money-in row with an MCC stays income.
