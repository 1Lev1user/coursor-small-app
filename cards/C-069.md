## Goal
CSV and Excel files that keep the merchant or payer name in one column and the payment details in another no longer lose the name. The Columns step gets an optional "Payee or sender" column; the name feeds the entry text, the saved rule keyword and the duplicate fingerprint, as it already does for camt and FiDAViSTA files. Today only one text column can be mapped, so for such files the rows are all called "Pirkums" (purchase) and the offered rule is "Remember for PIRKUMS".

## Notes
Source: D-bank.md problem 8 (VERIFIED on ASSUMED Swedbank-like and Citadele-like header shapes, probe p04_csv3.mjs B6, B2: "description = Pirkums; the payee SIA RIMI LATVIJA is not kept anywhere"); the user-facing symptom is in C2-power-user.md 1.2 and top finding 6 (description defaults to the generic "Detaļas" column, rule keyword PIRKUMS / LATVIJAS). Not part of D-bank-verify.md's 8 re-checks. Header names are ASSUMED from memory, no documented bank format was checked: verify with the owner's sample file.

Assumed shape (synthetic): `Datums;Saņēmēja/Maksātāja nosaukums;Maksājuma detaļas;Summa;Valūta;Atlikums` / `13.09.2026;SIA RIMI LATVIJA;Pirkums;-12,50;EUR;987,50`. Swedbank-like variant: `Saņēmējs/Maksātājs` for the name and `Informācija saņēmējam` for the details.

Design:
- New optional column key `counterparty`. `guessColumns` (text.js:336-489): headers whose normalised text contains `payee`, `counterparty`, `beneficiary`, `partneris`, `nosaukums`, `sanemejs`, `maksatajs`, `получатель`, `плательщик`. NOTE: "Informācija saņēmējam" normalises to "informacija sanemejam" and must NOT match (`sanemejam` does not contain `sanemejs`); add `informacija` to the description keywords (text.js:262) so that column is the description by keyword instead of by the content fallback. Process the new category after `description` in `CATEGORY_ORDER` (:265). Set `columns.counterparty` only when found (do NOT add it to `emptyColumns()`: importText.test.js:288 deepEquals the columns).
- `rowsToStatement` (text.js:854-865): `counterparty: cellAt(row, columns.counterparty)` (`statementRow` collapses whitespace).
- Columns step (import.js:870-873): `columnSelect(ctx, 'counterparty', 'Payee or sender (optional)', true, 'The shop or person. Used for the entry text and for rules.')` before Description; add `counterparty: -1` to the UI copy in startTable (:563).
- Saved layouts: a guessed payee column is NOT inherited by an already saved layout. The fingerprint (`core.js` `rowText`) includes the counterparty, so inheriting it would change the fingerprint of every row and break Exact matching against entries imported earlier with the same layout (research D-bank.md 11d). Extend `mergeSavedColumns` (C-064 / C-065) so `counterparty` always comes from the saved columns or -1. A newly saved layout stores it (`layoutRecord` spreads the columns).

Regression tests (new file, synthetic; `parseDelimited` -> `findHeaderRow` -> `guessColumns` -> `rowsToStatement`):
1. The failing input from the research: the Citadele-like shape above. EXPECTED: guessColumns gives counterparty = 1 and description = 2; the row has `counterparty` 'SIA RIMI LATVIJA' and `description` 'Pirkums'; `patternFor(row)` (import.js:105; `extractPattern` drops SIA and the trailing place word LATVIJA) is 'RIMI'. ACTUAL before: description 'Pirkums', no counterparty, pattern 'PIRKUMS'.
2. Swedbank-like header `Klienta konts;Ieraksta tips;Datums;Saņēmējs/Maksātājs;Informācija saņēmējam;Summa;Valūta;Debets/Kredīts`: counterparty is the Saņēmējs/Maksātājs column, description is `Informācija saņēmējam`, direction is the last column, amount unchanged (the existing guess test at importText.test.js:538 stays green).
3. A file with no payee-like header has no `counterparty` key in the guessed columns.
4. Header `Date;Payee;Reference;Amount` (the existing test at importText.test.js:653): `columns.bankRef` stays -1.
5. Two rows with the same bank text but different payees get different fingerprints (`fingerprint(row)` from core.js) and the same payee gives the same one.
6. `mergeSavedColumns` keeps the saved layout's absence of `counterparty` (-1) even when the new guess found one.
