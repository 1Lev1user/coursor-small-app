## Goal
A subscription row in a bank import is never matched silently: the import asks "Is this the Spotify subscription?" and the owner answers Yes or No; Yes marks the charge as the subscription's payment for that month, so its reminder stops (owner decision 11; part B of the split C-035).

## Acceptance
- `node --test test/subscriptionImportQuestion.test.js` exits 0
- `grep -c "subscription?" src/views/import.js` prints 1 or more
- `npm test` exits 0
- Manual (design-review): an import row with the question open and answered Yes, at 390, 768 and 1280 px, light and dark; owner checks
- Manual (owner): import a statement with a Spotify row for the current month while Spotify is a subscription: the row asks "Is this the Spotify subscription?"; Yes, import, and there is no reminder for Spotify that month; No, import, and the reminder still comes

## Do not touch
- src/model.js, SCHEMA_VERSION and MIGRATIONS
- style.css (the import rows already have `imp-hint` and `btn btn-ghost imp-link`)
- existing test files (test/importCore.test.js:225-231 asserts the exact keys of an imported expense and income without the new fields)
- Limit for `src/views/import.js`: one exported helper `suggestSubscription` next to `suggestSalary` (:146-162 at b6f8e05), one small shared question-line helper (question text, Yes, No, and the answered line with Undo; C-080 reuses it) and one block in `renderDecisionRow` (:1202-1378); nothing else.
- Limit for `src/import/core.js`: the `expenses.push` in `buildImport` (:522) only.
