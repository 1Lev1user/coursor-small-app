## Goal
Opening and closing balance lines that carry a date are no longer imported as income. Today a row such as `01.09.2026;Sākuma atlikums;;1000,00;K` is imported as +1000.00 income when the label is not in the column mapped as Description, or when the wording uses a word the app does not know ("beigās").

## Notes
Source: D-bank.md problem 4 (VERIFIED, probes p03 B3, p04 B5), independently confirmed in D-bank-verify.md item 3 (probe c3.mjs, both causes (a) label outside the Description column and (b) wording missing from the word list).

Cause: `isSummaryRow` (text.js:742-748) tests only the mapped Description cell with `isSummaryCell` when a description column is set (`labelCells`, :743); the keyword fallback `hasSummaryKeyword` applies only to rows WITHOUT a valid date (:747). The word list `SUMMARY_QUALIFIERS` (:709-715) has "beigu" but not "beigas" ("beigās" normalises to "beigas"), and no "brought", "forward".

Fix: test EVERY cell of the row with `isSummaryCell` (the whole cell must consist of known summary words and contain at least one core word, so an amount or a date can never match, and "TotalEnergies Riga" or "Saldo Bakery" still do not match), not only the description cell. Add qualifiers: `beigas`, `brought`, `forward`, `carried`. The Description-only behaviour for undated rows stays. Not in this card: flagging rows whose amount is far above the file median (research suggestion, needs UI).

Known side effect, accepted (research D-bank.md problem 4 "Minor related"): a merchant whose entire cell reads "Total" or "Balance" is dropped as a summary row; it is listed under skipped lines.

The fix (`if (row.some(isSummaryCell)) return true;` plus the added qualifiers) was prototyped by the planner on a copy of text.js: all 67 tests of importText.test.js pass and cases 1-5 below behave as listed.
