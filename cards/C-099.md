## Goal
A saved rule matches any text that merely contains its keyword: the rule RIMI also catches "PRIMI PIATTI RESTORANS" and "RIMINI PIZZA", and BOLT catches "BOLTON FURNITURE" (research/3.0/D-bank.md section 13, VERIFIED). Rows sorted by a rule are folded into a collapsed "Known" group, so a wrong match is not seen before Import. After this card:
- a rule matches only on word boundaries;
- keywords shorter than 3 letters or in a small stop list are never offered or matched;
- the Known group shows a one-line summary (how many rows went to which category) and stays easy to open.

## Notes
- `applyRules` (core.js ~276) uses `haystack.includes(pattern)`. `applyRuleToExisting` (~787) uses `matchText(...).includes(pattern)`.
- Use one shared matcher. A pattern matches when it occurs with a non-letter/digit (or the string edge) on both sides. Letters include Latvian letters (use \p{L}\p{N} with the u flag).
- Patterns ending in punctuation, such as 'BOLT.EU', still match 'BOLT.EUR2610' only if the next character is not a letter or digit. Planner: decide whether 'BOLT.EU' should keep matching the 'BOLT.EUR…' shape. A rule saved before this card must keep matching the rows it matched in the owner's real export: the orchestrator checks this locally.
- Stop list (never a keyword, never matched alone): PAR, UN, AR, NO, UZ, MAKSAJUMS, MAKSĀJUMS, PAYMENT, PIRKUMS, CARD, KARTE, SIA, AS, OU, UAB, LTD, LLC, GMBH, plus all LEGAL_FORMS.
- Existing importCore tests must stay green. If one asserts substring matching on purpose, STOP and report it: the owner must approve a test edit.
- Known group: keep `knownOpen` default false, but show "N rows sorted by your rules: Groceries 5, Transport 3" above the toggle.
- Tests:
