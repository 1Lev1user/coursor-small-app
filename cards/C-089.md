## Goal
Citadele (and other Latvian banks) put everything about a payment into one "Darījuma detaļas" cell. Today that whole cell becomes the row text, so a coffee is called "28/09/2026 490847******4322 MCC-5814 REF: 817028 LIDO ORIGO RIGA LV 54958376", the offered rule keyword is useless, and a transfer note keeps the other person's personal code and IBAN. After this card a card payment is called by its merchant ("LIDO ORIGO RIGA"), a transfer by the payer or payee ("TELE2 SIA") with the payment purpose as text, personal codes, BICs and IBANs are dropped, and a card payment carries the day it was really made (28.09) and its MCC code.

## Notes
Line shapes in the owner's file (2026-10-17, 71 rows: 62 card rows, 9 others; values below are made up in the same shape):
- Card payment, type PIRKUMS / PĀRSKAITĪJUMS NO KARTES: line 1 `28/09/2026 400000******0000 MCC-5814 REF: 100001`, line 2 `KAFEJNICA PARAUGS RIGA LV 10000001`. Line 2 ends with a 2-letter country code and an optional terminal id; examples `Bistro Riga Riga LV GPL72580`, `BOLT.EU/R/2610061652 Tallinn EE`, `Hotel at Booking.com Amsterdam NL`, `Revolut**6588* Dublin IE`.
- Card fee, type MAKSA PAR KARTI: one line, the card mask only (`400000******0000`).
- Incoming or outgoing transfer: line 1 purpose (`Darba algas izmaksa par 2026. gada septembri`, `Tele2 rēķins ?514995164?`, `Savstarpēji norēķini`), line 2 `NAME [reg. no. or personal code] [bank name] BIC IBAN`, for example `PARAUGS SIA 40000000000 HABALV22 LV00HABA0000000000001`, `JĀNIS PARAUGS 010190-12345 HABALV22XXX LV00HABA0000000000002`, `TELE2 SIA SWEDBANK AS IN LATVIA SWEDBANK AS LV00HABA0000000000003`, line 3 `Maksātāja reference: NOTPROVIDED` or another reference.

New module `src/import/details.js`, export `splitBankDetails(text, bookingDate)` → `{ description, counterparty, date, mcc }` (strings; `date` is 'YYYY-MM-DD' or '' when the booking date stays):
1. Card line: `^(\d{2})/(\d{2})/(\d{4})\s+\d{4,6}\*+\d{4}\s+MCC-(\d{4})\s+REF:\s*\S+` on the first line. counterparty = the next line without the trailing ` CC [terminal]` (country code `[A-Z]{2}` followed by an optional last token), description = '' . date = the card date when it is a real date 0 to 60 days before `bookingDate`; otherwise ''. mcc = the four digits.
2. Card fee line (a lone card mask): counterparty '', description 'Card fee' is NOT invented; keep the original text (the type column is not read in this card).
3. Transfer: the line holding an IBAN (`\b[A-Z]{2}\d{2}[A-Z0-9]{11,30}\b`) is the party line. counterparty = its text before the first of: a personal code `\d{6}-\d{5}`, an 11-digit registration number `\b\d{11}\b`, a bank phrase `\b[A-Z]+ AS IN LATVIA\b` / `\bAS "?[A-Z]+ BANKA"?\b`, a BIC `\b[A-Z]{6}[A-Z0-9]{2}([A-Z0-9]{3})?\b` directly before the IBAN, the IBAN. description = the lines above the party line joined with a space; the `Maksātāja reference:` line is dropped. Payer references are not bank references and are never put in bankRef.
4. Anything that matches none of the shapes: description = the text with whitespace collapsed, counterparty '', as today.
5. Personal codes, IBANs and card masks never reach description or counterparty in the split shapes.

`rowsToStatement` (text.js): read the raw description cell (with its line breaks), call `splitBankDetails(cell, date)`, use its description and counterparty, take `date` when non-empty, pass `mcc` to `statementRow`. Rows of other banks whose description has no such shape stay exactly as today (importText and importEndToEnd stay green).

Decision (owner asked the planner to decide, 2026-10-17): the card payment date is the entry date, because that is when the money was spent and when the owner types it by hand; the booking date is kept only when the card date is missing or implausible.

Tests (new file test/importDetails.test.js, all made-up data): each shape above; Latvian letters in names; the 60-day window (a card date after the booking date or 61 days before → ''); the personal-code and IBAN stripping; a camt-style single-line text without these shapes unchanged; `rowsToStatement` on a Citadele-shaped table gives counterparty, description, date and mcc per row.
