## Goal
A bank statement usually states the money on the account at its end. The owner's Citadele .xls has the line "Beigu atlikums: 429.15" (75.31 opening + 1685.37 in − 1331.53 out). Today the import skips it as a summary row and the number is lost. After this card every reader that can find it returns an optional `closingBalance: { cents, date }`, and the check panel shows "Bank balance on 17 Oct 2026: €429.15".

## Notes
Sources, in this order of trust (made-up test data in the documented shapes; research/3.1/bank-shapes.md):
- Table files (CSV, .xls, .xlsx, HTML, SpreadsheetML, paste): a summary line whose label is "Beigu atlikums", "Closing balance", "Ending balance", "Конечный остаток", "Lõppsaldo", "Galutinis likutis" (normalised, with or without a colon); the amount is the first amount cell on that line. The date is the period end from a preamble line ("līdz 2026-10-17", "to 17.10.2026") when present, otherwise the latest row date.
- A Balance / Running Balance / Atlikums column (Revolut, Wise, LHV): the balance on the row with the latest date (ties: the last such row in file order for oldest-first files, the first for newest-first files; the planner checks this against the existing order detection). Rows skipped as not completed do not count.
- Swedbank: the record-type 86 line (closing balance), amount with its D/K sign; one per currency, use the EUR one.
- camt: `Bal` whose `Tp/CdOrPrtry/Cd` is CLBD (amount sign from CdtDbtInd, date from Dt/Dt or DtTm); one per statement, use the last EUR statement.
- FiDAViSTA: `CloseBal` of the EUR CcyStmt; date = Period end.
- Only EUR balances are returned; otherwise no value.
- When several sources disagree inside one file, the explicit summary line or CLBD wins over a Balance column.
- Tests: the owner's shape (opening and closing lines around the rows, `līdz` in the preamble) gives 42915 on 2026-10-17; Revolut newest-first and oldest-first; Swedbank 86; camt CLBD with DBIT; FiDAViSTA; a file without any gives no value; the format matrix totals stay unchanged.
