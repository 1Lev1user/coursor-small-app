## Goal
Two Excel cases from the research (research/3.0/cards-bank.md, "Found but not carded", X4 and X6):
1. A date column whose cells are plain numbers without a date format (46296 instead of 01.10.2026) is "Date not recognised" on every row.
2. A workbook written by a program that stores formulas without their calculated value gives empty cells silently.

After this card:
1. A date column whose samples are all whole numbers between 20000 and 80000 (years 1954-2119) is read as Excel day numbers.
2. A sheet with formula cells that have no cached value returns a warning "This file has formulas that were never calculated. Open it in Excel and save it again."

## Notes
- 'SERIAL' in parseDateWith: /^\d{5}$/ in range → `excelSerialToDate(Number(value))` (import it from xlsx.js; text.js must not import the view).
- `inferDateFormat` returns 'SERIAL' only when every sample is such a number. This must not turn an amount column into a date: it applies only to the date column chosen by guessColumns.
- xlsx: an `<f>` element with no `<v>` → count it. When the count is > 0, return `{ ok: true, rows, warnings: [message] }`. Check that the wizard shows `warnings` for tables. If it does not, report it: import.js is outside this card, so the planner must say whether a follow-up is needed or the warning reaches the check panel already.
- Tests: serial dates in a CSV-like table; an amount column of 5-digit numbers is not treated as a date; an xlsx built in the test (reuse the zip writer pattern of test/importXlsx.test.js) with `<f>` and no `<v>`.
