## Goal
A statement with about 130 000 rows (allowed by the 10 MB limit) crashes the Columns step with "Maximum call stack size exceeded", because the widest row is found with `Math.max(...rows.map(...))` (research/3.0/D-bank.md section 17, VERIFIED; src/views/import.js:878 and :889). After this card the width is computed with a loop, so any file within the size limit opens.

## Acceptance
- `node --test test/importLargeFile.test.js` exits 0
- `node --test test/importLargeFile.test.js 2>&1 | grep -E '^# pass ([2-9]|[1-9][0-9])'` exits 0
- `grep -c "Math.max(\.\.\." src/views/import.js | grep -qx 0` exits 0
- `npm test` exits 0

## Do not touch
- existing test files
- Limit for `src/views/import.js`: `columnOptions` and `previewTable` width computation only (export a small pure helper for the width if the test needs it).

## Notes
- Replace both spreads with a reduce or loop helper `widestRow(rows)` that returns 0 for an empty list.
- Tests: `widestRow` with 200 000 generated rows returns the right width without throwing, and with an empty list returns 0. If import.js cannot be imported in Node without a DOM, test through the exported helper only. importDetectMt940Ofx.test.js already imports import.js, so it can be imported.
