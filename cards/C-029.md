## Notes
One schema step for the whole slice, so the owner's devices convert once and C-007's pre-update copy covers the whole money change. Later cards add no fields; they only use these. Never assume a field exists on an entry created in the same session (the import builds entries without `sourceId`; test/importCore.test.js:246 asserts the exact income keys): treat missing as ''.

Owner decisions this card carries (research/3.0/decisions-3.0.md): 2 (past months stay as they are), 3 (no weekend rule, so no weekend field), 4 (no amount matching, so no matching field), 8 (a bank check is one dated difference entry), 9 (no opt-in switch field: the new counting starts at the 3.0 update after a one-time setup).

model.js (line numbers of today's file, verify before editing):
- :1 `SCHEMA_VERSION = 2` becomes 3. `defaultData()` (:69-142) gains settings `balanceStart: null`, `perDayMode: 'auto'`, `perDayFixedCents: 0`, and top-level `incomeSources: []`, `balanceAdjustments: []`. `version` stays `SCHEMA_VERSION`.
- Meaning of the new fields (the later cards rely on exactly this):
  - `settings.balanceStart`: null, or `{ cents: integer (may be negative), date: 'YYYY-MM-DD' }`. Null means the one-time 3.0 money setup (C-034) has not been done on this data: every month still counts the old way and the app shows that setup before Home. When it is set, it is the money on hand at the start of `date` (C-038), and the month of `date` is the first month counted the new way (C-030 `usesNewCounting`). Only the setup writes it and nothing edits it afterwards. It is not an opt-in switch: there is no setting for it, and the setup cannot be skipped.
  - `settings.perDayMode`: 'auto' or 'fixed' (C-038, C-039). `settings.perDayFixedCents`: integer >= 0, used only in 'fixed' mode.
  - `incomeSources[]`: `{ id, name, incomeCategoryId, expectedCents (integer >= 0), dayOfMonth (1-31), startDate ('YYYY-MM-DD' or ''), skippedMonths (array of 'YYYY-MM') }`. `startDate` is the day the source was added; a payday on or before it is never asked about (C-030).
  - `balanceAdjustments[]`: `{ id, date ('YYYY-MM-DD'), cents (non-zero integer, signed) }`: the one dated difference that "Check against the bank" adds (C-038, C-039). It changes Money now only, never a month's income or spending.
  - `incomes[].sourceId`: string, '' when the entry is not tied to a source. Set only when the user picks the source in Add income or confirms the payday reminder (C-036).
  - `subscriptions[].skippedMonths`: array of 'YYYY-MM' the owner skipped (C-035).
- Export `normaliseIncomeSource(raw)`: returns null when `raw` is not an object or has no non-empty string `id`; otherwise a clean object with the fields above (name trimmed and cut to 40 characters; `expectedCents` not an integer >= 0 becomes 0; `dayOfMonth` not an integer 1-31 becomes 1; bad `startDate` becomes ''; `skippedMonths` filtered to valid month keys, de-duplicated; `incomeCategoryId` a string, else '').
- Export `normaliseAdjustment(raw)`: returns null unless `raw` is an object with a non-empty string `id`, a valid date (use `monthKeyOf` from months.js) and a non-zero integer `cents`; otherwise `{ id, date, cents }`.
- `normaliseEntry` (:155-172): when `!isExpense`, `entry.sourceId = stringOr(entry.sourceId)`. Do not touch the expense branch (an expense may carry `subscriptionId` already; C-035 sets it from the import and it must survive).
- `MIGRATIONS[2]` after `MIGRATIONS[1]` (:178-190), same style: deep copy, `version = 3`, `settings = { ...settings, balanceStart: null, perDayMode: 'auto', perDayFixedCents: 0 }`, `incomeSources = []`, `balanceAdjustments = []`, incomes get `sourceId: ''` (keep an existing string), subscriptions get `skippedMonths: []`. No record is dropped or reordered. The step must not read the clock (the migration must be repeatable).
- `normalise` (:219-356): after the existing settings handling (:261-282) repair the new fields the way the neighbours are repaired: `balanceStart` must be an object with an integer `cents` and a date that passes `monthKeyOf` else null; `perDayMode` not 'auto' or 'fixed' becomes 'auto'; `perDayFixedCents` not an integer >= 0 becomes 0; `incomeSources` and `balanceAdjustments` not an array become []; map through `normaliseIncomeSource` / `normaliseAdjustment` and drop nulls; each subscription gets `skippedMonths` repaired the same way (accept subscriptions without the field, test/subscriptions.test.js builds them without it). Import `monthKeyOf` from months.js.
