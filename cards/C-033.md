## Goal
The owner lists his regular incomes (name, usual amount, payday, weekend rule, category) in Settings, and a user of the old rule can switch to payday counting with one button.

Model it on the Subscriptions section, which does the same job for expenses: src/views/settings/subscriptions.js (list :280-326 rows, add form :328-438, edit, delete confirm). Use `element, persist, buildField, setError, clearError, actionButton, renderConfirm` from shared.js:73, 193, 201, 216, 223, 230, 237. New file `src/views/settings/incomeSources.js`, exports `renderIncomeSourcesSection(ctx)`, `describeIncomeSource(source)` and `legacyIncomeNotice(data)`.
- Section id `more-income-sources`, heading 'Regular income'. In more.js import it, add `['more-income-sources', 'Paydays']` to the jump list (more.js:29-39, after Plan) and put the section after `renderPlanSection(ctx)` (more.js:49) and before `renderIncomeSection(ctx)`. Add './src/views/settings/incomeSources.js' to CORE_ASSETS in sw.js (test/serviceWorker.test.js fails otherwise).
- Intro text: 'Add each regular income with the day it arrives. On that day the app asks you to confirm the real amount, so a different salary each month is fine. Income is counted when it arrives, not from the 1st.'
- List: one row per `ctx.data.incomeSources` with name, `describeIncomeSource(source)` = `'EUR 2,000.00 · day 25 · weekend: day before'` (formatEuro from money.js; weekend text 'stays on that day' / 'day before (Friday)' / 'day after (Monday)'), and a status line for the current month from `incomeStatus(ctx.data, currentMonthKey(), new Date())`: 'This month: received EUR 2,150.00', 'This month: expected 25 Oct', 'This month: confirm now', 'This month: skipped'. Edit and Delete buttons like subscriptions; Delete confirm text: `Delete ${name}? Income you already recorded stays.` Empty list: 'No regular income yet.'
- Add and edit form fields: Name, 'Usual amount (EUR)', 'Payday (day of month)', select 'If payday is on a weekend' (options keep / before / after with the texts above), select 'Income category' (all `ctx.data.incomeCategories`, default 'salary' when present). Validation and creation go through `validateIncomeSource`, `addIncomeSource`, `updateIncomeSource`, `deleteIncomeSource` from src/incomeSources.js (C-030); show the returned `reason` on the returned `field`. Toasts: 'Regular income added', 'Regular income saved', 'Regular income deleted'. The cap error from `canAddIncomeSource` shows as the form error.
- Old-rule notice (`legacyIncomeNotice(data)` returns the text or null): when `settings.incomeSourcesFrom === ''` and `settings.usualMonthlyIncomeCents > 0`: `Your usual income of ${formatEuro(usual)} is counted from the 1st of every month, even before it arrives. Add it with its payday to count it on the day it arrives. Earlier months stay as they are.` and a button 'Set payday for this income' that fills the add form with name 'Salary', the usual amount (formatPlain) and category salary, and focuses the day field. When the first source is saved, `addIncomeSource` sets `incomeSourcesFrom` to the current month (C-030), so the notice disappears. Never delete or change `usualMonthlyIncomeCents` here.

test/incomeSourcesView.test.js (new): `describeIncomeSource` for the three weekend rules; `legacyIncomeNotice` returns text for old-rule data with usual 200000, null when `incomeSourcesFrom` is '2026-10', null when usual is 0; the notice text names the formatted amount. (The DOM is not tested; the pure helpers are, as test/uiHelpers.test.js does for add.js.)
