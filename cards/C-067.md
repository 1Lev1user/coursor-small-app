## Goal
A camt entry that bundles several payments (one `Ntry` with several `TxDtls`, for example a salary run or a bulk payment) is imported as one row per payment when the parts add up to the entry amount, each with its own payee, text and reference. Today the entry becomes ONE row with the first payee as counterparty and all texts joined, so a saved rule for the first payee would be applied to the whole batch; a foreign amount in one part also relabels the whole row.

## Notes
Source: D-bank.md problem 10 (batch entries C4, C5; VERIFIED behaviour, real-bank semantics UNVERIFIED; probes p07_camt.mjs, p11_camt2.mjs), independently confirmed in D-bank-verify.md item 7 (probe c7.mjs: one `Ntry` Amt 60.00 DBIT with three `TxDtls` 10/20/30, parties Alpha/Beta/Gamma gives ONE row `out 6000`, description "Invoice A Invoice B Invoice C", counterparty "Alpha", bankRef "B1", no warning). Whether the owner's bank sends batches, and whether the per-payment amount is `NtryDtls/TxDtls/AmtDtls/TxAmt/Amt` (as in the research probe and importXml.test.js) or another element, is UNVERIFIED: verify with the owner's sample file. Element names in the card come from the existing parser and probes, not from the ISO 20022 schema.

Cause: `camtEntry` (src/import/xml.js:472-527) returns one `statementRow`; `camtParty` (:436-445) and `camtDescription` (:447-455) read the first/all `TxDtls` of the entry; `camtCounterAmounts` (:421-434) searches `NtryDtls/TxDtls/AmtDtls` across ALL `TxDtls`, so one foreign `TxAmt` relabels the whole entry (research C5: a 60.00 EUR row labelled USD with original 35.00).

Design:
- In `camtEntry` (or a helper it calls), when the booked entry has 2 or more `NtryDtls/TxDtls`, read each part's amount (`AmtDtls/TxAmt/Amt`). Split only when EVERY part has an amount in the entry currency and the parts sum exactly to the entry amount in cents. Each part becomes a row: same date and direction, the part's amount, description from its `RmtInf/Ustrd` (or `AddtlTxInf`), counterparty from its own `RltdPties/Cdtr` or `Dbtr` by direction, bankRef from its `Refs/AcctSvcrRef`, else `Refs/EndToEndId` unless it is NOTPROVIDED (`cleanRef` :457-470 shows the rules), else `<entry bankRef>-<n>`. Foreign counter amounts are looked up inside that part only (make `camtCounterAmounts` take a node).
- `camtEntry` therefore returns a row or an array of rows; `parseCamt` (:547-556) flattens. Single-`TxDtls` entries and entries with no `NtryDtls` are untouched.
- When the parts cannot be split (amount missing, other currency, or sums differ) keep ONE row but with an empty counterparty (so a rule cannot be built on the first payee) and add a warning through `skippedWarnings`' counts: `N batch entries could not be split into single payments and were read as one row.`
- Consequence to state in the PR description: a statement imported with the old parser and imported again shows the split rows as new (the old single row had another amount and another reference). Weak matching needs the same amount within 2 days and will not catch it. Acceptable only because batches are rare; the owner is told in _index.

Regression tests (new file, synthetic; wrapper and entry builder as in C-066, plus a part builder):
`<TxDtls><Refs><AcctSvcrRef>T1</AcctSvcrRef></Refs><AmtDtls><TxAmt><Amt Ccy="EUR">10.00</Amt></TxAmt></AmtDtls><RltdPties><Cdtr><Nm>Alpha</Nm></Cdtr></RltdPties><RmtInf><Ustrd>Invoice A</Ustrd></RmtInf></TxDtls>`
1. The failing input from the research: entry `B1` Amt 60.00 DBIT with parts 10.00 Alpha / 20.00 Beta / 30.00 Gamma (texts Invoice A, B, C; refs T1, T2, T3). EXPECTED: 3 rows `out` 1000, 2000, 3000 with counterparties Alpha, Beta, Gamma, descriptions Invoice A, B, C, bankRefs T1, T2, T3. ACTUAL before: one row 6000, counterparty Alpha, description "Invoice A Invoice B Invoice C", bankRef B1.
2. Parts that do not add up (10.00 + 20.00 + 25.00 against 60.00): ONE row 6000 with empty counterparty and a warning that mentions 1 batch entry.
3. Research C5: batch of 3 parts where the second part also has `<InstdAmt><Amt Ccy="USD">35.00</Amt></InstdAmt>`: 3 rows; only the second has currency 'USD' and `originalAmountCents` 3500; the others are EUR with original equal to the amount.
4. A part without an amount: not split, warning.
5. Parts without their own reference get `B1-1`, `B1-2`, `B1-3`.
6. Control: an entry with one `TxDtls` and an entry with no `NtryDtls` give exactly one row, as today (re-run the existing fixtures).
7. Two statements in one file, one with a batch: only that entry is split.
