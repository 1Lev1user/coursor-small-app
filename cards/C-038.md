## Notes
Owner decisions (research/3.0/decisions-3.0.md): 1 savings (goal contributions) leave Money now and are shown as a separate amount; 6 Home shows Money now, then the per-day amount, then the month budget; 7 per-day amount in two modes chosen by the user: (a) a fixed amount set by the user, showing what is left of today's amount, (b) automatic: Money now divided by the days left until the next payday, or until the month end when there is no payday, recalculated after every entry; 8 "Check against the bank" adds one dated difference entry and past months stay unchanged; 9 the counting starts at the one-time setup.

Design, all of it derived rather than stored (stored balances would drift with every edit, Undo, import undo and restore): the anchor `settings.balanceStart = { cents, date }` means "the money I had at the start of that date", so entries dated on the anchor date count. Money now at a day is the anchor, plus income entries, minus expenses (`spendCents` from budget.js:19, so a refund adds money back), plus bank-check differences, all dated from the anchor date to the end of that day. Entries dated after the day asked about are ignored (a Netflix row dated next week does not lower Money now). Expected income that was not confirmed is not money and never counts. Savings leave Money now with no special rule: a goal contribution is an expense in the Savings category (goals.js:187-219), so it lowers Money now like any expense; `savedCents` reports it separately. Bank-import transfers are not entries and are ignored.

Exports of src/balance.js (C-034 and C-039 import these names; import `SAVINGS_ID` from model.js, `spendCents` from budget.js, `incomeStatus` from incomeSources.js, and the date helpers from months.js; add a local `daysBetween(fromISO, toISO)` using `Date.UTC`):
- `parseBalanceInput(text)`: an optional leading '-' followed by `parseAmount(rest, { allowZero: true })` (money.js; it picks up C-044's thousands separators when that card is merged), returns integer cents or null.
- `balanceAt(data, dateISO)`: null when there is no anchor or `dateISO < anchor.date`; otherwise `anchor.cents` plus the income entries, minus the `spendCents` of the expenses, plus the `balanceAdjustments`, with `anchor.date <= date <= dateISO`.
- `moneyNow(data, now)` = `balanceAt(data, todayISO(now))`.
- `setMoneyNow(data, enteredCents, now)`: the one-time setup (C-034). `{ ok: false, reason: 'Money now is already set.' }` when `balanceStart` exists; `{ ok: false, reason: 'Enter a valid amount.' }` when `enteredCents` is not a safe integer; otherwise it anchors at today so that `moneyNow` equals what was entered even when entries dated today already exist: set the anchor to `{ cents: 0, date: todayISO(now) }`, read `balanceAt` for today, then set `anchor.cents = enteredCents - thatNet`. Returns `{ ok: true }`.
- `checkAgainstBank(data, enteredCents, now)`: "How much is on the card now?". `{ ok: false, reason: 'Set up Money now first.' }` without an anchor, `{ ok: false, reason: 'Enter a valid amount.' }` for a bad number. Otherwise `differenceCents = enteredCents - moneyNow(data, now)`; when it is 0 nothing is added and it returns `{ ok: true, differenceCents: 0, adjustment: null }`; else it pushes `{ id: createId('adj'), date: todayISO(now), cents: differenceCents }` to `data.balanceAdjustments` and returns `{ ok: true, differenceCents, adjustment }`. It never touches a month's income or spending, so past months and the budget stay as they are.
- `deleteBankCheck(data, id)`: removes that adjustment and returns true; false for an unknown id (the owner's undo, C-039).
- `savedCents(data, now)`: the net `spendCents` of the Savings-category expenses dated from the anchor date to today (null without an anchor). This is the separate "savings" amount.
- `nextPayday(data, now)`: the earliest payday date strictly after today among `incomeStatus` items (C-030) with state 'upcoming' in the current and the next month; `{ date, sourceId, name }` or null. A payday that is today or earlier and not yet confirmed is ignored (money may be arriving; it is not a horizon), and so is a received or skipped one.
- `perDay(data, now)`: null without an anchor. Mode `settings.perDayMode`.
  - 'auto': horizon = `nextPayday(...).date` (`untilKind: 'payday'`, `paydayName`), or when there is none the first day of next month (`untilKind: 'monthEnd'`); `days = daysBetween(today, horizon)`, at least 1; `amountCents = Math.floor(moneyNow / days)` (negative when Money now is negative: the screen says nothing is left). Because it is computed from Money now each time, it is recalculated after every entry. Returns `{ mode: 'auto', amountCents, days, untilDate, untilKind, paydayName, moneyCents }`.
  - 'fixed': `amountCents = settings.perDayFixedCents`; `spentTodayCents` = the net `spendCents` of the expenses dated today that are not in the Savings category (money set aside is not spending); `leftTodayCents = amountCents - spentTodayCents` (negative when over). Returns `{ mode: 'fixed', amountCents, spentTodayCents, leftTodayCents, moneyCents }`.
- `setPerDay(data, mode, amountText)`: the settings form's save. Mode must be 'auto' or 'fixed' else `{ ok: false, reason: 'Choose a mode.' }`; 'fixed' needs `parseAmount(amountText)` (greater than zero) else `{ ok: false, reason: 'Enter a valid amount greater than zero.' }` and sets `perDayFixedCents`; 'auto' keeps the stored fixed amount. Returns `{ ok: true }`.
- `monthBalance(data, monthKey)`: null when no anchor or the month is before the anchor's month; else `{ openingCents, closingCents, startsOn }`. In the anchor's own month `openingCents = anchor.cents` and `startsOn = anchor.date`; in later months `openingCents = balanceAt(data, last day of the previous month)` and `startsOn` is the first day of the month. `closingCents = balanceAt(data, last day of monthKey)`. A month's opening always equals the previous month's closing.

Not done on purpose: unpaid subscriptions are not subtracted from the per-day amount (the owner's decision 7 says Money now divided by the days); an unconfirmed payday today does not shorten the horizon.

Worked numbers for tests (2026 calendar; `balanceStart` `{ cents: 100000, date: '2026-10-01' }`; income 150000 on 2026-10-05; expense 25000 on 2026-10-10; now `new Date(2026, 9, 15)`):
- `moneyNow` = 225000. A 30000 expense dated 2026-10-20 does not change it. A 4000 refund (`refund: true`) on 2026-10-12 raises it to 229000.
- An entry dated 2026-09-30 is ignored. `balanceAt(data, '2026-09-30')` is null; without an anchor `moneyNow` is null.
- `checkAgainstBank(data, 230000, now)` returns `differenceCents` 5000, pushes `{ date: '2026-10-15', cents: 5000 }`, `moneyNow` is then 230000, and `monthTotals` of October and September are deep-equal to before (past months unchanged); entering exactly `moneyNow` returns 0 and adds nothing; entering 220000 pushes -5000; an adjustment dated 2026-10-20 does not count at now; `deleteBankCheck` brings the old figure back; no anchor returns the reason.
- `setMoneyNow` on data with no anchor and one 1000 expense dated 2026-10-04, now 4 Oct: entering 125050 gives `moneyNow` 125050 and `anchor.cents` 126050; a second call returns 'Money now is already set.'.
- Savings: a 10000 expense in the Savings category on 2026-10-12 lowers `moneyNow` by 10000 and `savedCents` is 10000; a 2000 refund in Savings makes it 8000.
- `perDay` auto, no sources: `untilKind` 'monthEnd', `days` 17 (15 Oct to 1 Nov), `amountCents` 13235 (225000 / 17 rounded down). With source Salary 200000 day 25 (`startDate` '2026-10-01', not received): `nextPayday` is 2026-10-25, `days` 10, `amountCents` 22500, `paydayName` 'Salary', `untilKind` 'payday'. Today 25 Oct with the salary unconfirmed: horizon 2026-11-25, `days` 31. Salary received in October by an entry tied to the source: horizon 2026-11-25, `days` 41 at now 15 Oct. October skipped: same November horizon. 31 Oct with no sources: `days` 1.
- `perDay` fixed 3000: with an expense of 1200 and a refund of 200 dated today and a 5000 Savings expense today, `spentTodayCents` 1000 and `leftTodayCents` 2000; expenses of other days are not counted; with fixed 500 `leftTodayCents` is -500. Auto mode ignores `perDayFixedCents`.
- `setPerDay(data, 'fixed', '30')` sets 3000; `'0'` and 'abc' are refused with the message; `'auto'` keeps 3000; mode 'x' is refused.
- `monthBalance(data, '2026-10')` with the 30000 expense dated 2026-10-20 added: opening 100000, `startsOn` '2026-10-01', closing 195000 (includes entries after `now`); `monthBalance(data, '2026-11').openingCents` is 195000; '2026-09' is null.
- `parseBalanceInput('-12,50')` is -1250, '0' is 0, 'abc' and '' are null.
