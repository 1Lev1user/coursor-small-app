## Goal
The inline edit forms in Settings > Subscriptions, Regular income and Quick add no longer show about 120 px of empty space under every field: each field is as tall as its label, input and message.

## Acceptance
- `node --test test/inlineFormStack.test.js` exits 0
- `npm test` exits 0
- Manual (design-review): the edit form of a subscription, a regular income and a quick-add template, and the Month entry editor (unchanged row layout), at 390, 768 and 1280 px, light and dark; owner checks

## Do not touch
- src/ (the class names `inline-form entry-edit-form stack` stay)
- existing test files
- Limit for `style.css`: one new rule next to `.inline-form .field`.

## Notes
Found by the C-046 review on 2026-10-05 (the C-033 review saw the same gaps). The forms in src/views/settings/subscriptions.js:184, src/views/settings/incomeSources.js:135 and src/views/settings/templates.js use `inline-form entry-edit-form stack`. `.stack` turns the form into a column, and `.inline-form .field { flex: 1 1 12rem; }` (style.css about :1272) then gives every field a 12rem flex-basis along the column axis, so each field is 192 px tall. The Month editor and Settings > Income use `inline-form entry-edit-form` without `stack` (a wrapping row), where the 12rem basis is a width and correct.

Fix: add, right after `.inline-form .field`, `.inline-form.stack .field { flex: 0 0 auto; }` (tokens are not involved). Do not change `.inline-form .field` itself, so the row forms keep their layout.

Test `test/inlineFormStack.test.js` (new; style.css read as text, comments stripped, same brace-walker technique as test/cssRules.test.js): a rule whose selector list includes `.inline-form.stack .field` exists, its body sets `flex` to `0 0 auto`, it comes after the `.inline-form .field` rule in the file, and the `.inline-form .field` rule still has `flex: 1 1 12rem`. The test fails on the current CSS.
