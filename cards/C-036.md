## Goal
On and after a payday the app asks "Income due", pre-filled with the expected amount and the payday date; the owner types what really arrived (it may differ from month to month), and a real income entry is created.

## Acceptance
- `node --test test/incomeConfirm.test.js` exits 0
- `node --test test/incomeConfirm.test.js 2>&1 | grep -E '^# pass ([5-9]|[1-9][0-9])'` exits 0
- `FROZEN_DATE=2027-03-10 node --import ./scripts/frozen-date.mjs --test test/incomeConfirm.test.js` exits 0
- `grep -c "Income due" src/app.js` prints 1 or more
- `npm test` exits 0
- Manual (design-review): the Income due screen (default, with an error, after a missed month) at 390, 768 and 1280 px, light and dark; owner checks
- Manual (owner): source Salary 2,000 day 1, today after the 1st: the screen shows on any tab; typing 2,150.00 and Confirm adds an income entry "Salary" 2,150.00 dated the payday in Month and the month income shows 2,150.00 (expected 0); Later closes it until reload; Skip this month removes it for the month; reload keeps the entry
- Manual (owner): close the app over a payday, open it three days later: one screen for the missed month, dated the payday

## Notes
Pattern to reuse: the subscription reminder in app.js (`duePrompt` :44-49, `confirmDueSubscription` :154-196 with its rollback on a failed save, `renderDuePrompt` :279-403, `attachDueTrap` :251-277, `render()` due block :509-515, `postponedDue` from C-035). Income and subscription screens never show together: income first, then subscriptions.

incomeSources.js: add `confirmIncome(data, source, monthKey, { amountText, date })`:
- amount through `parseAmount` (money.js; zero is refused, comma decimals accepted); invalid gives `{ ok: false, field: 'amount', reason: 'Enter a valid amount greater than zero.' }`.
- date must pass `monthKeyOf(date) !== null` and be in `monthKey` (the due month), else `{ ok: false, field: 'date', reason: \`Pick a date in ${monthLabel(monthKey)}.\` }`. This keeps the entry in the month it is paying for, so `incomeStatus` sees it as received.
- success: remember `planWasAlreadyFrozen = Object.hasOwn(data.monthPlans, monthKey)`, push `{ id: createId('inc'), incomeCategoryId: source.incomeCategoryId, amountCents, note: source.name, date, sourceId: source.id }` (the same minimal shape add.js:947-953 uses; `normalise` fills the rest on load), call `freezeMonthPlan(data, monthKey)` (budget.js:182), return `{ ok: true, entry, planWasAlreadyFrozen }`. Import `freezeMonthPlan` from './budget.js' only if that does not create a cycle (budget.js imports incomeSources.js since C-031); if it does, create the snapshot in app.js instead and keep `confirmIncome` free of it.

app.js:
- `render()` due block: `const dueIncome = dueIncomes(app.data).find(not in postponedDue)`; if present `renderIncomePrompt(dueIncome)`, else the subscription logic from C-035. `removeDueOverlay` (:150-152) removes both overlay ids ('due-subscription-overlay' and a new 'due-income-overlay'). Keep the `setupComplete` and storage-issue paths that already remove the overlay (:424, :484-489).
- `renderIncomePrompt({ source, monthKey, date, expectedCents })`: same structure and classes as `renderDuePrompt`: `due-overlay`, `due-card stack`, `role="dialog"`, `aria-modal`, focus trap through `attachDueTrap`. Title 'Income due'. Name = `source.name`. Meta = `Expected ${formatEuro(expectedCents)} · ${monthLabel(monthKey)} · payday ${shortDate(date)}`. Fields: 'Amount (EUR)' prefilled with `formatPlain(expectedCents, '.')` and 'Date' (`type="date"`, prefilled with the payday `date`, `min` and `max` the first and last day of `monthKey`). Actions: Confirm (primary), Later, Skip this month. No Delete here (sources are managed in Settings). Keep the typed values and the error in a module-level `incomeDraft` (like `duePrompt`) so a re-render does not lose them; reset it when the item changes.
- Confirm: `confirmIncome`; on `ok: false` show `reason` under the named field and keep the screen; on `ok: true` call `save()`; if `save()` returns false remove the pushed entry (`app.data.incomes.splice`) and delete the snapshot when `planWasAlreadyFrozen` was false (same rollback as :179-193), keep the screen. Success toast 'Income recorded'.
- Later (button, Escape, backdrop click): add `income:${source.id}:${monthKey}` to `postponedDue` and render again. Skip this month: `skipIncomeMonth(app.data, source.id, monthKey)` (C-030), `save()`, rollback on failure, toast 'Skipped for this month'.
- `dueIncomes` already returns missed months oldest first (C-030), so a closed app catches up one screen per month.

test/incomeConfirm.test.js (new, fixed `now`): (1) `confirmIncome` with '2150,00' and the payday date creates an entry with `sourceId`, `incomeCategoryId` of the source, `amountCents` 215000, then `incomeStatus` for that month reports state 'received' and `receivedCents` 215000 and `dueIncomes` no longer lists it; (2) the month plan for that month exists afterwards; (3) '0' and 'abc' return field 'amount'; (4) a date in the next month returns field 'date' and pushes nothing; (5) `skipIncomeMonth` removes it from `dueIncomes`.

Unverified: the date input `min`/`max` behaviour on iOS Safari is not checked; the validation in `confirmIncome` is the real guard.
