## Goal
On the payday of a regular income, Home shows "Salary expected today: €2,000.00" with an editable amount and the buttons Received, Later and Skip this month; nothing is added without the owner. In Add income the owner picks which regular income he is recording, and only a picked source counts as received for that month.

## Notes
Owner decisions (research/3.0/decisions-3.0.md): 5 on payday with no entry yet, a reminder on Home "Salary expected today: EUR X" with Received (amount editable), Later, Skip this month, and nothing is added without the user; 3 payday is exactly the set date, so the user postpones, skips or cancels himself; 4 an income counts for a source only when the user picks that source in Add income; 10 in Add income the sources are in the list, the picked source counts as received for that month; 15 income is added with Add income on Home.

incomeSources.js: add `confirmIncome(data, source, monthKey, { amountText })`:
- amount through `parseAmount` (money.js; zero is refused, comma decimals accepted); invalid gives `{ ok: false, field: 'amount', reason: 'Enter a valid amount greater than zero.' }`.
- success: push `{ id: createId('inc'), incomeCategoryId: source.incomeCategoryId, amountCents, note: source.name, date: paydayDate(monthKey, source), sourceId: source.id }` (the minimal shape add.js:951-957 uses; `normalise` fills the rest on load) and return `{ ok: true, entry }`. The entry is dated the payday, also for a payday that passed while the app was closed, so the entry sits in the month it pays for and `incomeStatus` sees it as received. It never freezes a plan (budget.js imports this file since C-031, so importing budget.js here would be a cycle); the caller does.

src/views/paydayReminder.js (new; add './src/views/paydayReminder.js' to CORE_ASSETS in sw.js). No `document` access at module top level.
- `export function reminderTitle(item, now = new Date())`: `item` is a `dueIncomes` item (C-030). Payday today: `${source.name} expected today: ${formatEuro(expectedCents)}`; an earlier payday: `${source.name} expected on ${shortDate(date)}: ${formatEuro(expectedCents)}`.
- `export function renderPaydayReminders(ctx)`: returns a container with one card per item of `dueIncomes(ctx.data, new Date())` that is not postponed (oldest first), or null when there is none. Card: `section.card.stack` with `aria-label` the title, the title as a bold line, a field 'Amount received (EUR)' prefilled with `formatPlain(expectedCents, '.')`, and three buttons: Received (primary), Later, Skip this month. A module-level `postponed` Set holds `${source.id}:${monthKey}` for Later (it lasts until the page is reloaded) and a module-level draft map keeps typed text and an error per key, so a re-render does not lose them.
- Received: `confirmIncome`; on `ok: false` show `reason` under the amount field (`setError` pattern as in add.js) and keep the card; on `ok: true` remember `planWasAlreadyFrozen = Object.hasOwn(ctx.data.monthPlans, monthKey)`, call `freezeMonthPlan(ctx.data, monthKey)` (budget.js), then `ctx.save()`; when it returns false remove the pushed entry (`ctx.data.incomes.splice`) and delete the snapshot when `planWasAlreadyFrozen` was false (same rollback as add.js:594-603), and keep the card. Success toast 'Income recorded'.
- Later: add the key to `postponed`, `ctx.render()`. Skip this month: `skipIncomeMonth(ctx.data, source.id, monthKey)` (C-030), `ctx.save()`; on a failed save remove the month key again; toast 'Skipped for this month'.
- Several cards can show at once (two incomes, or a missed month); there is no cap beyond the 12-month window of `dueIncomes`.
