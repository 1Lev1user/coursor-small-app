## Goal
In the Columns step of the import wizard, below the "N rows are ready to import" line, show what was actually read: three parsed rows from the top and the last row, the total money in and total money out in EUR, how many rows were read and skipped, and the number of lines in the file against the number of rows read. A person comparing it with the bank's own totals catches a wrong decimal separator, wrong direction, a balance line counted as income, or lost lines by eye. Today the step only shows raw cells, so these errors surface at Categorise or never.

## Notes
Source: D-bank.md "Suggested fix order" step 3 and problems 1, 2, 4, 5, 6: this panel "would have caught 1, 2, 4, 5 and 6 by eye". Reconciliation idea from B-research.md section 3 (statement totals as a check value). Not independently confirmed as a feature; the problems it exposes were (D-bank-verify.md items 1-5).

Pure helper (exported, tested): `checkSummary(rows, skipped, { fileLines = null, tableRows = null } = {})` in src/views/import.js, returning
`{ read, skippedCount, totalInCents, totalOutCents, foreignCount, sample, oneDirection, lineMismatch }`.
- `read` = rows.length; `skippedCount` = skipped.length.
- totals sum `amountCents` of rows where `Number.isInteger(amountCents)` by direction; rows with `amountCents === null` (foreign currency still needing an EUR amount) are not summed and counted in `foreignCount`.
- `sample` = first 3 rows plus the last row when there are more than 4 (the last row exposes a footer or closing balance line).
- `oneDirection` = 'in' or 'out' when there are at least 5 rows and at least 90 percent of them have that direction, else null. This is the "every row is money in" warning for unsigned amounts without a direction column (D-bank.md problem 2, input D).
- `lineMismatch` = `{ fileLines, tableRows }` when both are numbers and differ, else null.

Rendering in `renderColumns` (src/views/import.js:825-954), only when `parsed.rows.length > 0`: a labelled region "Check what was read" with the sample rows (use `amountText` :428 and `describeRow` :436, date as stored), "Money in EUR x" and "Money out EUR y" (`formatEuro`), "Rows read: N, skipped: M", and the warnings as plain sentences: oneDirection ("Almost every row is money in (28 of 30). If your bank shows spending as positive numbers, check the Direction column."); lineMismatch ("The file has 42 lines but 31 rows were read. Some lines may have been joined together; look for a stray quote mark."). Warnings are informational, never block Continue. A multi-line quoted cell can legitimately produce a lineMismatch; the wording says "may".

Line count source: `readStatementFile` (:462-490) adds `lineCount` for CSV = number of non-blank physical lines of the decoded text (`text.split(/\r\n|\r|\n/)`, blank lines dropped); `loadPaste` (:516-532) counts the same on the pasted text; Excel gets null (rows are exact by construction). `acceptLoaded` stores it in a new `state.fileLines` (also in `freshState`, :277). `tableRows` = `state.table.rows.length`. Do not change the shape of the existing return values beyond adding `lineCount` (the MT940/OFX tests use `ok`, `format`, `reason`).

Saved-layout path: when a saved layout fits, the wizard skips the Columns step (startTable :583-598), so the panel does not show. Open owner decision (see _index): also show it above the Duplicates list in that case. Not part of this card.

Regression tests (new file, synthetic; build rows with `rowsToStatement`, call `checkSummary` directly):
1. Wrong decimal separator as it happens today: file `Datums;Apraksts;Summa` / `13.09.2026;S0;-12,50 EUR` / `14.09.2026;S1;-3,20 EUR` parsed with decimalSeparator '.' gives totalOutCents 157000; parsed with ',' gives 1570. Test asserts the helper reports exactly the sums of the rows it is given and that `sample[0]` is the first row.
2. All-income input (research problem 2): 6 rows `RIMI`, `MAXIMA`, ... with unsigned amounts `12,50` and direction values the app does not know -> `oneDirection === 'in'`; 3 rows of each direction -> null; 4 rows all 'in' -> null (needs at least 5).
3. Stray quote (research problem 5): 30-row file `Date;Description;Amount` / `2026-03-NN;Shop N;-N,00` with `Pizza 12" large` in row 5: `lineMismatch` equals `{ fileLines: 31, tableRows: 6 }` when the current tokenizer is used. If C-060 has already landed the test builds the mismatch from handed-in numbers instead (the helper test must not depend on the tokenizer).
4. Dated opening balance leaking in as income (research problem 4): rows `+1000.00` (Sākuma atlikums) and `-12.50` -> totalInCents 100000, so a person sees "Money in 1,000.00" against a salary-less file.
5. Foreign rows: a row with `amountCents: null` is excluded from totals and counted in `foreignCount`.
6. `sample` has first 3 plus last when 10 rows; exactly the rows when 3.
