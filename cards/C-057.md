## Goal
Every bank import shows what was actually read before anything is saved: three parsed rows from the top and the last row, the total money in and total money out in EUR, how many rows were read and skipped, and the number of lines in the file against the number of rows read. A person comparing it with the bank's own totals catches a wrong decimal separator, wrong direction, a balance line counted as income, or lost lines by eye. Today the Columns step shows only raw cells, so these errors surface at Categorise or never.

The panel is in the Columns step, and also at the top of the Duplicates step whenever the Columns step was skipped: a remembered bank layout, a camt file or a FiDAViSTA file (owner decision 21, research/3.0/decisions-3.0.md). It matters most for a remembered layout, because a bank can change its format under a saved layout and the person never sees the columns again.

Also in this card, because it is the first bank card that edits src/views/import.js: the step counter no longer says "Step 1 of 4" on the Load step and "Step 2 of 5" on the next one. While the file format is not known yet the Load step reads "Step 1"; afterwards "Step n of N" (hand-off from research/3.0/cards-ux.md, "Not carded").

Pure helpers (exported, tested), all in src/views/import.js:
- `checkSummary(rows, skipped, { fileLines = null, tableRows = null } = {})` returning `{ read, skippedCount, totalInCents, totalOutCents, foreignCount, inCount, sample, mostlyIn, lineMismatch }`.
  - `read` = rows.length; `skippedCount` = skipped.length; `inCount` = rows with direction 'in'.
  - totals sum `amountCents` of rows where `Number.isInteger(amountCents)` by direction; rows with `amountCents === null` (foreign currency still needing an EUR amount) are not summed and counted in `foreignCount`.
  - `sample` = first 3 rows plus the last row when there are more than 4 (the last row exposes a footer or closing balance line).
  - `mostlyIn` = true when there are at least 5 rows and at least 90 percent of them are money in. This is the "every row is money in" warning for unsigned amounts without a direction column (D-bank.md problem 2, input D). Money out is deliberately not flagged: a card statement is legitimately almost all spending, and a warning on every such file would be ignored.
  - `lineMismatch` = `{ fileLines, tableRows }` when both are numbers and differ, else null.
- `checkPanelPlacement(step, { tabular, savedLayoutName })` returns `'columns'` for the Columns step; `'saved'` for the Duplicates step when the format is tabular and `savedLayoutName !== ''` (that field is set only when a remembered layout skipped the Columns step and is cleared by Continue in the Columns step, so a person who went through the Columns step does not see the panel twice); `'file'` for the Duplicates step when the format is not tabular (camt, FiDAViSTA); otherwise null.
- `checkWarnings(summary, placement)` returns plain sentences, informational, never blocking Continue:
  - `mostlyIn`, placement 'columns': "Almost every row is money in (28 of 30). If your bank shows spending as positive numbers, check the Direction column."
  - `mostlyIn`, placement 'saved': "Almost every row is money in (28 of 30). The saved columns may no longer fit this file: use Change columns above and check the Direction column."
  - `mostlyIn`, placement 'file': no sentence (camt and FiDAViSTA carry an explicit direction).
  - `lineMismatch` (any placement): "The file has 42 lines but 31 rows were read. Some lines may have been joined together; look for a stray quote mark." A multi-line quoted cell can legitimately produce a mismatch; the wording says "may".
- `stepCountText(index, total, formatKnown)` returns `Step 1` when `formatKnown` is false and index is 0, otherwise `Step ${index + 1} of ${total}`.
