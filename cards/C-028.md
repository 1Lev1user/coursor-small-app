## Goal
File picker accepts MT940 and OFX/QFX files so their message can be shown.

## Acceptance
- `node --test test/importAcceptList.test.js` exits 0
- `npm test` exits 0
- Manual (owner): on the phone, the file picker lets you choose a .sta or .ofx file and the app shows the "export CSV or camt" message

## Do not touch
- src/import/
- existing test files
- Limit for `src/views/import.js`: the input.accept list only.

## Notes
Follow-up from the C-008 plan. The import file input accepts '.csv,.txt,.xlsx,.xls,.xml' (src/views/import.js, input.accept, about line 705), so MT940 (.sta, .mt940) and OFX/QFX (.ofx, .qfx) files cannot be picked and the C-008 message is only reached for such files saved as .txt or .xml. Add '.sta,.mt940,.ofx,.qfx' to the accept list. Owner decision C6/C7 stands: these files are recognised and the user is asked for CSV or camt; no parsers. The new test reads src/views/import.js as text and asserts that the accept string contains each of the four extensions and still contains the existing five. Verify the line number against main before editing.
