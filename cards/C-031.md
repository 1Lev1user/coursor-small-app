## Goal
From the month of the one-time 3.0 setup on, monthTotals counts only income entries: every salary is its own dated entry and the old usual income is never added on top. Months before that keep the old rule, except that a month the owner never had (no data and before his first month) no longer shows income.

## Notes
Owner decisions (research/3.0/decisions-3.0.md): 2 past months before 3.0 stay as they are, from the switch on every month's salary is its own dated entry with its own amount and never changes earlier months; 4 no guessing, an income belongs to a source only when the user picked it (C-036); 9 the new counting starts at the one-time setup; 12 plan changes apply from the current month on.

Today `monthTotals(data, monthKey)` (budget.js:200-252) adds the plan's usual income to the month from day 1 (budget.js:237-238) for any month, past, future or never used, and a manual Salary entry is added on top (hasImportedSalary needs an importId, budget.js:26-31). Findings behind this card: the first Home after setup shows a review card for a month the owner never had; Month shows 2,000 income for September 2025; a manual Salary of 2,000 makes the month income 4,150.

New signature: `monthTotals(data, monthKey, now = new Date())`; `incomeBreakdown(data, monthKey, now = new Date())`. Existing callers keep working unchanged (default `now`); analytics.js:18 and monthReview.js:22 pass the `now` they already hold.

Rules, in this order, using `usesNewCounting`, `incomeStatus`, `monthIncomeSplit`, `firstTrackedMonth` from src/incomeSources.js (C-030):
1. Month does not use the new counting (`usesNewCounting` false, which is every month while `settings.balanceStart` is null): `usualIncomeCents = plannedIncomeCents(...)` as today, with one new guard: it is 0 when the month has no expense, no income and no frozen plan, and `compareMonthKeys(monthKey, firstTrackedMonth(data, now)) < 0` (a month before the owner's first month). This is the only change to a past month and it only removes income from months with no data at all. Months with data, or on/after the first month, behave exactly as before.
2. Month uses the new counting: `usualIncomeCents = 0` whatever `usualMonthlyIncomeCents` says (the setting stays stored so older months keep their numbers). `incomeCents` is the sum of all income entries of the month. Split with `monthIncomeSplit`: entries tied to an existing source are `sourceIncomeCents` (the salary), the rest are `extraIncomeCents`. A salary typed without picking the source is extra income: the app does not guess (decision 4).
3. New result fields (add, do not rename or remove any existing field): `sourceIncomeCents`; `expectedIncomeCents` = sum of `expectedCents` of the sources whose `incomeStatus` item is 'upcoming' or 'due' in that month (not 'received' or 'skipped'), 0 for months on the old rule. `cashLeftCents` stays `incomeCents - spentCents`, so expected income never counts as money.
4. `incomeBreakdown` follows the same split: no 'Usual salary (Plan)' row for months on the new counting (its `usualIncomeCents` is 0 there) and `extraIncomeCents` is the part not tied to a source; otherwise unchanged. Keep the returned field names (test/budget.test.js:571-640 asserts them).
5. Future months on the new counting show expected income only (state 'upcoming'), received 0. Future months on the old rule are unchanged (known gap, accepted).

analytics.js:17-32 (`actualTotals`) keeps stripping the usual income for months not in use or not yet happened; it only gains `now` for `monthTotals`. test/analytics.test.js and the Year view must produce the same numbers as today for old-rule data.

monthReview.js:22: after rule 1's guard, a new owner who finished setup on 4 Oct sees no review for September (both totals are 0, line 23 returns null). Add a second explicit guard right after line 17: return null when `compareMonthKeys(previousKey, firstTrackedMonth(data, now)) < 0`.

test/incomeModel.test.js (new, `now` fixed in every call) must assert, each with a number:

4. 5. An entry tied to the source (`sourceId`) of 215000 on 25 Oct: `incomeCents` 215000, `sourceIncomeCents` 215000, `extraIncomeCents` 0, `expectedIncomeCents` 0. An untagged Salary-category entry of 200000 on the same day: `extraIncomeCents` 200000, `sourceIncomeCents` 0 and `expectedIncomeCents` still 200000 (no guessing from the category or amount).
