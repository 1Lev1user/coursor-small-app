## Goal
monthTotals counts only income that really arrived: in payday months from real entries (a manual or imported Salary entry is the salary, not an extra on top), and the old usual income never appears for months before the owner started or for a month already past that has no data.

## Notes
Today `monthTotals(data, monthKey)` (budget.js:200-252) adds the plan's usual income to the month from day 1 (budget.js:237-238) for any month, past, future or never used, and a manual Salary entry is added on top (hasImportedSalary needs an importId, budget.js:26-31). Findings behind this card: the first Home after setup shows a review card for a month the owner never had; Month shows 2,000 income for September 2025; a manual Salary of 2,000 makes the month income 4,150.

New signature: `monthTotals(data, monthKey, now = new Date())`; `incomeBreakdown(data, monthKey, now = new Date())`. Existing callers keep working unchanged (default `now`); analytics.js:18 and monthReview.js:22 pass the `now` they already hold.

Rules, in this order, using `usesIncomeSources`, `incomeStatus`, `matchIncomes`, `trackingStartMonth` from src/incomeSources.js (C-030):
1. Month uses the old rule (`usesIncomeSources` false): `usualIncomeCents = plannedIncomeCents(...)` as today, with one new guard: it is 0 when the month has no expense, no income and no frozen plan, and `compareMonthKeys(monthKey, trackingStartMonth(data, now)) < 0` (a month before the owner started). Months with data, or on/after the start, behave exactly as before.
2. Month uses income sources: `usualIncomeCents = 0`. Real income entries of the month are split: entries matched to a source (`matchIncomes`, claiming each entry once across sources) are `sourceIncomeCents`; the rest are `extraIncomeCents`. `incomeCents = usualIncomeCents + sourceIncomeCents + extraIncomeCents`. A manual Salary entry of 2,150 against a 2,000 source is therefore received salary, not a second income.
3. New result fields (add, do not rename or remove any existing field): `sourceIncomeCents`; `expectedIncomeCents` = sum of `expectedCents` of sources whose state is 'upcoming' or 'due' (not 'received', 'skipped' or 'missed') in that month, 0 for the old rule; `forecastIncomeCents = incomeCents + expectedIncomeCents`; `cashLeftForecastCents = forecastIncomeCents - spentCents`. `cashLeftCents` stays `incomeCents - spentCents`, so expected income never counts as money.
4. `incomeBreakdown` follows the same split: no 'Usual salary (Plan)' row for months on income sources (its `usualIncomeCents` is 0 there), otherwise unchanged. Keep the returned field names (test/budget.test.js:571-640 asserts them).
5. Future months: on income sources they show expected income only (state 'upcoming'), received 0. The old rule for future months is unchanged (known gap, accepted; owners move to income sources in C-033).

analytics.js:17-32 (`actualTotals`) keeps stripping the usual income for months not in use or not yet happened; it only gains `now` for `monthTotals`. test/analytics.test.js and the Year view must produce the same numbers as today for old-rule data.

monthReview.js:22: with rule 1's guard, a new owner who finished setup on 4 Oct sees no review for September (both totals are 0, line 23 returns null). Add a second explicit guard right after line 17: return null when `compareMonthKeys(previousKey, trackingStartMonth(data, now)) < 0`.

test/incomeModel.test.js (new, `now` fixed in every call) must assert, each with a number:
1. Old rule unchanged: `incomeSourcesFrom: ''`, usual 200000, month with an entry: `usualIncomeCents` 200000.
2. Phantom guard: `trackingStartMonth` '2026-10', no entries, `monthTotals(data, '2026-09', new Date(2026, 9, 4))` has `incomeCents` 0 and `cashLeftCents` 0; same for '2025-09'.
3. `getMonthReviewSuggestion(data, new Date(2026, 9, 4))` is null for that data.
4. Payday model: `incomeSourcesFrom: '2026-10'`, usual 200000, source Salary 200000 day 25: at 15 Oct `incomeCents` 0, `expectedIncomeCents` 200000, `forecastIncomeCents` 200000, `cashLeftCents` equals minus spent; at 25 Oct with no entry still `incomeCents` 0 (due, not received).
5. Manual Salary entry 215000 on 25 Oct, no sourceId: `incomeCents` 215000, `sourceIncomeCents` 215000, `extraIncomeCents` 0, `expectedIncomeCents` 0 (no double count); an extra Bonus 10000 on 26 Oct adds to `extraIncomeCents` only.
6. A month before `incomeSourcesFrom` keeps the old rule (September 2026 with usual 200000 and an entry gives 200000).
7. Two sources on days 5 and 25: after the first is received at 15 Oct, `expectedIncomeCents` is the second source's amount only.
8. November (now 15 Oct) with `incomeSourcesFrom` set: `incomeCents` 0, `expectedIncomeCents` the sum of active sources.
9. Imported salary (entry with `importId`, category salary) in a payday month is matched like a manual one.
