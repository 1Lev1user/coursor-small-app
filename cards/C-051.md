## Goal
On a desktop the app content is a centred column of about 736 px instead of 1,216 px inputs and 1,200 px buttons; the Year by-category table at 320 px scrolls inside its card instead of clipping the Share column and breaking names mid-word; and the faded zero-value rows in the Chart legend keep text contrast above 4.5:1.

## Acceptance
- `node --test test/layoutCss.test.js` exits 0
- `node --test test/contrast.test.js` exits 0
- `npm test` exits 0
- Manual (design-review): Home, Month, Chart (Spending with a zero-value row, Year with a long amount) and Settings at 320, 390, 768 and 1280 px, light and dark; at 1280 px the header title, the content and the tab bar share one centred column; no horizontal page scroll at 320 px; owner checks
- Manual (owner): at 1280 px the Add expense button is no wider than the column; at 320 px open Chart > Year with an amount of 99,999.99 in a long-named category: the table scrolls sideways inside its card with every column readable

## Do not touch
- SCHEMA_VERSION and MIGRATIONS
- Any colour token value (test/contrast.test.js checks them)
- JavaScript files (this card is CSS only)
- The mobile layout at 390 px: values for narrow widths stay as they are
- existing test files
- Limit for `style.css`: the rules named in Notes only; new values come from tokens or the one new token.

## Notes
Source: C3 F26 (screenshots c3-06-settings-desktop-top.png, c3-45-desktop-home.png: no max width, inputs 1,216 px wide, mobile bottom tab bar on desktop), C2 7.2 ("Add EUR400 to Savings" is a 1,200 px bar, c2-85, c2-86), C3 F21 (c3-31-narrow-year.png: the by-category table is 346 px in a 288 px card, "Share" clipped, names break as "Necessar y expense s"), C3 F18 (c3-15-money-chart.png: zero-value legend rows at opacity 0.55 give "no limit" 2.61:1 light and 3.15:1 dark, names 3.71:1 light; WCAG AA needs 4.5:1, process/design-review.md). Line numbers are from `main-work` at 05d1355; verify before editing. These numbers were measured by the tester with a script; the card's own test asserts the CSS, the contrast itself is checked by eye with the screenshots.

1. Content width. Add one layout token next to `--tabbar-height` and `--tap` (:130-131): `--content-max: 46rem;`. `#view` (:260-268): add `max-width: var(--content-max); margin-inline: auto;` (keep its padding). `.app-header` (:243-252, a `padding` shorthand: split it into block and inline parts first) and `.tabbar` (:278-291, `padding-inline` at :289) keep their full-width background but centre their content with `padding-inline: max(calc(var(--s4) + env(safe-area-inset-left)), calc((100% - var(--content-max)) / 2))` (use the right inset for the right side). The fixed `.rights-mark` (:225-243) and the `.toast` (:916-931) stay as they are. A side navigation for wide screens (C3 suggestion) is not part of this card.
2. Year table. `.data-table tbody th` (:2044-2047): replace `overflow-wrap: anywhere` with `overflow-wrap: break-word` and add `min-width: 7rem`; `.year-category-table` (new rule): `min-width: 17rem`. The wrapper `.bars-table-wrap` (:2019-2022) already has `overflow-x: auto`, so with a minimum width the table scrolls inside its card instead of being squeezed. `.card` has `overflow-x: clip` (:333); that does not stop an inner scroller. Reproduce the clipping at 320 px before changing anything; if the table already scrolls, change nothing in this item and report it in the pull request description.
3. Faded rows. `.chart-legend-button:disabled` (:720-723) loses `opacity: 0.55`. Replace it with a lighter swatch only: `.chart-legend-button:disabled .chart-swatch { opacity: 0.45; }`; the name and amount keep their normal token colours (`--text`, `--muted`), which test/contrast.test.js already checks at 4.5:1 on `--surface`. The zero amount still shows "EUR 0.00" and the row stays non-clickable (`cursor: default`).

Tests, new `test/layoutCss.test.js` (read `style.css` as text, same technique as test/contrast.test.js; extract a rule body with a small helper that finds the selector and the next closing brace): `:root` defines `--content-max`; the `#view` rule contains `max-width: var(--content-max)`; the `.chart-legend-button:disabled` rule body has no `opacity`; a rule `.chart-legend-button:disabled .chart-swatch` exists; the `.data-table tbody th` rule has no `overflow-wrap: anywhere`; a `.year-category-table` rule has `min-width`.
