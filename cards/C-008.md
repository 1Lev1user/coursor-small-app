## Notes
detectFormat (detect.js:89) today knows only camt, fidavista, csv. Add: 'ofx' when the body (after BOM/trim) starts with 'OFXHEADER:' (OFX 1.x SGML header) or is XML whose root (rootElement detect.js:8, which already skips <?...?>) is OFX (OFX 2.x and QFX); 'mt940' when lines start with ':20:' and ':25:' and ':60F:' or ':60M:' (optionally after a '{1:..}{2:..}{4:' SWIFT header). Both run before looksDelimited: an MT940 line like ':61:2609250925D12,50NTRFNONREF' has one comma and can pass as CSV. In src/views/import.js export readStatementFile (:456) and after detectFormat (:472) return {ok:false, reason}: mt940 -> 'This looks like an MT940 statement. The app cannot read MT940 yet. Export the same statement as CSV or camt.053 XML.'; ofx -> same with 'OFX/QFX' (decision C6/C7: no MT940 or OFX parsers are built; this message is final). Tests (>=5, synthetic text, labelled synthetic): MT940 with and without SWIFT header; MT940 with commas is not 'csv'; OFX 1.x SGML; OFX 2.x XML; a CSV sample is still 'csv'; readStatementFile(new File([mt940], 'stmt.sta')) -> ok false, reason /MT940/ (Node 22 global File).
