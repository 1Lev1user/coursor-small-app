## Goal
The header row is found when a CSV header has a different number of cells than the data rows (a trailing `;` on one side) and when Excel rows are shorter than the header because trailing blank cells were dropped. A wide text-only preamble line is no longer mistaken for the header. Today no header is found, nothing is guessed, "Remember these columns" never saves, and the user maps every column by hand on every import.

## Notes
Source: D-bank.md problems 6 and 7 (second part, wide preamble row; VERIFIED, probes p02 A1/A2, p06 X5/X8, p13 G1), the width mismatch (problem 6) is independently confirmed in D-bank-verify.md item 5 (probes c5.mjs, c5b.mjs); the wide-preamble-row part (problem 7, G1) was not re-checked there. The user can still map columns by hand (rows skipped as "Date not recognised" for the header line), so this is CONFUSING rather than data-wrong, but it also disables saved layouts for these files.

Cause: `findHeaderRow` (text.js:205-248) accepts only a row whose `row.length` equals the dominant row length (`row.length !== dominant`, :232). A header of 3 cells over data rows of 4 (trailing `;`), the reverse, an XLSX header of 4 over data rows that end with a blank cell (trimmed to 3), or a split Debets/Kredits sheet (debit rows 3 cells, credit rows 4, header 4) never matches.

Fix outline: take the header to be the nearest row above the first row that contains a date-like cell (use `isDateLikeValue`, text.js:281; XLSX dates arrive as `YYYY-MM-DD`) that is all text (`isNumericOrDateCell`, :182) and has at least `max(2, ceil(width / 2))` non-empty cells, where width is the dominant length of the rows with trailing empty cells trimmed. Width is therefore not compared for equality. If no row contains a date-like cell (textual dates like "17 Sep 2026"), keep today's rule unchanged. Headerless data (first row already a data row) must still return -1.

The outline was prototyped by the planner on a copy of text.js: all 67 tests of importText.test.js pass, and cases 1-5 below give the expected indexes (0, 0, 2, 0, 0, 1). Sketch: `trimmedLength(row)` = index of the last non-blank cell + 1; `dominant` = most frequent trimmed length among rows with trimmed length 2 or more (ties go to the larger); `firstData` = index of the first row with a date-like cell; walk upward from `firstData - 1` and return the first row whose non-empty cells number at least `max(2, ceil(dominant / 2))` and none of them is numeric or date-like; when `firstData` is -1 use the old equal-width loop.

Regression tests (new file, synthetic; use `parseDelimited` for CSV and plain arrays for XLSX-shaped rows):
1. The failing input from the research: header `Date;Description;Amount` (3 cells), 10 data rows like `2026-03-01;Shop 1;-1,00;` (trailing `;`, 4 cells). EXPECTED `findHeaderRow(rows) === 0`. ACTUAL before: -1 (guessColumns then asks "Choose the date column", 0 rows imported).
2. The reverse: header `Date;Description;Amount;` (4 cells), data rows with 3 cells: 0.
3. The same two files with two preamble lines in front (`Konts;LV00TEST`, `Periods;2026-03`): 2.
4. XLSX-shaped: header `['Datums','Apraksts','Summa','Atsauce']` and data rows `['2026-09-01','RIMI','-12,50']` (last cell blank trimmed), most rows 3 cells: 0. Split sheet: header `['Datums','Apraksts','Debets','Kredīts']`, debit rows 3 cells, credit rows 4 cells: 0.
5. Wide preamble row taken as header (research G1): rows `['Klients','Jānis Bērziņš','Konts','LV00TEST','','','','']` above an 8-column header and 5 data rows with dates: returns the index of the real header, not 0.
6. End to end: after (1) `guessColumns` finds date, description and amount, and `rowsToStatement` returns 10 rows with no skipped lines for the header.
7. Controls: headerless pasted data still -1; `'Konta izraksts;;;;'` title line above the header is not chosen.
