## Goal
One tested module that answers, for every income source and month, when payday is, what is expected, what was received and what is due now. No screen changes.

## Notes
Data shape comes from C-029 (`data.incomeSources[]`, `incomes[].sourceId`, `settings.incomeSourcesFrom`, `settings.trackingStartMonth`). Pure functions; every function that depends on today takes `now` (a `Date`, default `new Date()`), tests pass a fixed `now` (AGENTS.md). Import `todayISO, currentMonthKey, monthKeyOf, addMonths, compareMonthKeys, dateInMonth, daysInMonth, clampDay, isInMonth` from months.js, `earliestDataMonth, createId` from model.js. months.js has no weekday helper: compute it with `new Date(Date.UTC(y, m - 1, d)).getUTCDay()` (0 = Sunday).

limits.js: `export const MAX_INCOME_SOURCES = 10;` and `canAddIncomeSource(data)` returning `{ ok: true }` or `{ ok: false, reason: 'You can have at most 10 income sources.' }` (pattern at limits.js:36-44).

Exports of src/incomeSources.js (the next cards import these names):
- `trackingStartMonth(data, now)`: the earlier of `settings.trackingStartMonth` (when valid) and `earliestDataMonth(data)`; when both are empty, `currentMonthKey(now)`.
- `usesIncomeSources(data, monthKey)`: true when `settings.incomeSourcesFrom !== ''` and `compareMonthKeys(monthKey, incomeSourcesFrom) >= 0`.
- `paydayDate(monthKey, source)`: 'YYYY-MM-DD'. Day = `clampDay(monthKey, source.dayOfMonth)` (day 31 in November is 30 Nov). Weekend rule: 'keep' returns that day; 'before' moves a Saturday or Sunday back to the Friday; 'after' moves it forward to the Monday; if the move would leave the month, return the unmoved day. Tests (2026 calendar, 25 Oct 2026 is a Sunday, 24 Oct a Saturday): day 25 keep = 2026-10-25, before = 2026-10-23, after = 2026-10-26; day 24 before = 2026-10-23; day 1 in Nov 2026 (a Sunday) before = 2026-11-01 (would leave the month); day 31 in Jan 2026 (a Saturday) after = 2026-01-31; day 31 in Nov 2026 keep = 2026-11-30.
- `matchIncomes(data, source, monthKey, claimed = new Set())`: income entries of that month that count as this source. An entry counts when `entry.sourceId === source.id` (all such entries count), or when it has no sourceId, is not in `claimed`, has `incomeCategoryId === source.incomeCategoryId`, `source.expectedCents > 0`, and `Math.abs(amountCents - expectedCents) <= expectedCents * 0.25` (this covers a manual "Salary" entry and a bank-imported salary, so neither is counted twice). Only the closest such untagged entry is taken. The caller adds the taken ids to `claimed` so two sources never claim one entry. Return `{ entries, receivedCents }`.
- `incomeStatus(data, monthKey, now)`: array, one item per active source in the model for that month, in the order of `data.incomeSources`: `{ sourceId, name, incomeCategoryId, date: paydayDate, expectedCents, receivedCents, entryIds, state }`. Only when `usesIncomeSources(data, monthKey)` and the month is not before `source.startMonth` (when set); otherwise an empty array. `state`: 'received' (matched entries exist), else 'skipped' (monthKey in `skippedMonths`), else 'missed' (month before the current month of `now`), else 'due' (`date <= todayISO(now)`), else 'upcoming'.
- `dueIncomes(data, now)`: items with state 'due' or 'missed' for every month from the later of `incomeSourcesFrom`, `source.startMonth` and (current month minus 11) up to the current month, oldest first, as `{ source, monthKey, date, expectedCents, state }`. Empty when `incomeSourcesFrom === ''`. This is the catch-up for months the app was closed.
- `validateIncomeSource(data, fields)` for forms. `fields` are raw strings: `{ name, amount, dayOfMonth, weekendRule, incomeCategoryId }`. Returns `{ ok: true, value }` (a source body without id) or `{ ok: false, field: 'name'|'amount'|'day'|'category', reason }` with the same messages the subscription form uses: 'Enter a name.', 'Enter a valid amount greater than zero.', 'Enter a day from 1 to 31.', 'Choose an income category.'. Use `parseAmount` from money.js. Name 1 to 40 characters after trim.
- `addIncomeSource(data, value, now)`: checks `canAddIncomeSource`, pushes `{ id: createId('incsrc'), ...value, active: true, startMonth: currentMonthKey(now), skippedMonths: [] }`, and when `data.settings.incomeSourcesFrom === ''` sets it to `currentMonthKey(now)`. Returns `{ ok, source }`. `updateIncomeSource(data, id, value)` replaces name, amount, day, rule, category; `deleteIncomeSource(data, id)` removes it and leaves entries (their `sourceId` then points nowhere, which every function here ignores); `skipIncomeMonth(data, id, monthKey)` adds the month once. All return false/`{ ok: false }` for an unknown id.
- `nextPaydayAfter` is NOT part of this card (C-038 owns it).

Tests must also assert: a source with `incomeSourcesFrom: ''` yields no status and no due item (old rule untouched); with `incomeSourcesFrom: '2026-10'`, now 15 Oct 2026, source day 25 keep: state 'upcoming', then at now 25 Oct: 'due'; an income tagged `sourceId` of 2150.00 on 25 Oct: 'received', receivedCents 215000; an untagged Salary entry of 2150.00 matches a 2000.00 source, an untagged 4000.00 does not; two sources of the same category claim two different entries; skipped month: 'skipped' and not in `dueIncomes`; at now 3 Nov a never-confirmed October payday is 'missed' and appears in `dueIncomes` with `monthKey` '2026-10'; a month before `startMonth` has no status.

Unverified: the 25 % matching tolerance and the 12-month catch-up window are proposals (owner decisions listed in _index); change the two constants `MATCH_TOLERANCE` and `CATCH_UP_MONTHS` at the top of the file if the owner decides otherwise.
