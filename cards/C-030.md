## Goal
One tested module that answers, for every income source and month, when payday is, what is expected, what was received and what is due now, and which source a bank-import income row might belong to (only suggested; the owner confirms). An income counts for a source only when the user tied it to that source; the module never guesses from an amount or a category. No screen changes.

## Notes
Owner decisions (research/3.0/decisions-3.0.md): 3 payday is exactly the set date, no weekend rule; 4 no guessing, no amount matching; 9 the new counting starts at the one-time setup; 10 several incomes, each a source; 12 changes apply from the current month on. Data shape comes from C-029: `data.incomeSources[]`, `incomes[].sourceId`, `settings.balanceStart`. Pure functions; every function that depends on today takes `now` (a `Date`, default `new Date()`), tests pass a fixed `now` (AGENTS.md). Import `todayISO, currentMonthKey, monthKeyOf, addMonths, compareMonthKeys, dateInMonth, isInMonth` from months.js and `createId` from model.js. This module must not import budget.js (budget.js imports it from C-031 on; an import cycle would break the module load).

limits.js: `export const MAX_INCOME_SOURCES = 10;` and `canAddIncomeSource(data)` returning `{ ok: true }` or `{ ok: false, reason: 'You can have at most 10 income sources.' }` (pattern at limits.js:31-39).

Exports of src/incomeSources.js (the next cards import these names):
- `countingStartMonth(data)`: `monthKeyOf(settings.balanceStart.date)` when `balanceStart` is set, else ''.
- `usesNewCounting(data, monthKey)`: true when `countingStartMonth(data) !== ''` and `compareMonthKeys(monthKey, countingStartMonth(data)) >= 0`. A month that returns false keeps the old rule exactly (decision 2: past months stay as they are).
- `earliestDataMonth(data)`: the smallest month key over `expenses[].date`, `incomes[].date` and `Object.keys(monthPlans)`, '' when there is none.
- `firstTrackedMonth(data, now)`: `earliestDataMonth(data)` when not empty, else `countingStartMonth(data)` when not empty, else `currentMonthKey(now)`. C-031 and C-032 use it to tell a month the owner never had.
- `paydayDate(monthKey, source)`: `dateInMonth(monthKey, source.dayOfMonth)`. Day 31 in November is 30 Nov; day 30 in February 2027 is 28 Feb. There is no weekend rule: the date is the date.
- `incomeStatus(data, monthKey, now)`: an empty array unless `usesNewCounting(data, monthKey)`; otherwise one item per source, in the order of `data.incomeSources`: `{ sourceId, name, incomeCategoryId, date: paydayDate, expectedCents, receivedCents, entryIds, state }`. `received` = income entries of that month with `sourceId === source.id` (all of them are added up; a second entry adds to the first). `state`, first match wins: 'received' (at least one such entry); 'skipped' (monthKey in `skippedMonths`); no item at all when `source.startDate !== ''` and the payday is on or before `startDate` (the source did not exist yet, or the payday has already passed on the day it was added); 'upcoming' (payday after today); otherwise 'due' (payday is today or earlier). An entry without a `sourceId`, or with an id of a source that no longer exists, belongs to no source, whatever its category or amount.
- `dueIncomes(data, now)`: items with state 'due', for every month from the latest of `countingStartMonth`, the source's `startDate` month and (current month minus `CATCH_UP_MONTHS - 1`) up to the current month, as `{ source, monthKey, date, expectedCents }`, oldest payday first. `export const CATCH_UP_MONTHS = 12;`. Empty when `countingStartMonth(data) === ''`. This is the catch-up for paydays that passed while the app was closed.
- `monthIncomeSplit(data, monthKey)`: `{ sourceIncomeCents, extraIncomeCents, totalCents }` over the income entries of that month; an entry counts as source income when its `sourceId` equals the id of an existing source, otherwise as extra.
- `suggestIncomeSource(data, row, takenKeys = new Set(), now = new Date())`: the helper behind the import's question "Is this the <source name>?" (C-035). `row` is an import row `{ date, direction, ... }`. Returns the source (or null) whose payday in the row's own month is within `PAYDAY_MATCH_DAYS` days of `row.date`, the amount being irrelevant; `export const PAYDAY_MATCH_DAYS = 5;`. All must hold: `row.direction === 'in'`; `usesNewCounting(data, monthKeyOf(row.date))`; `incomeStatus` has an item for that source and month whose state is not 'received' (a received payday needs no question; 'upcoming', 'due' and 'skipped' all may ask); `${source.id}:${monthKey}` is not in `takenKeys` (a month is asked once per import). With several candidates the one whose payday is closest to the row date wins, the earlier in `data.incomeSources` on a tie. The distance is the whole days between two dates (use `Date.UTC`). It only suggests: nothing is tied unless the owner answers Yes, so decision 4 (no automatic matching) holds. Paydays near a month end are not matched across months.
- `validateIncomeSource(fields)` for forms. `fields` are raw strings: `{ name, amount, dayOfMonth, incomeCategoryId }`. Returns `{ ok: true, value }` (a source body without id, startDate and skippedMonths) or `{ ok: false, field: 'name'|'amount'|'day'|'category', reason }` with the messages the subscription form uses: 'Enter a name.', 'Enter a valid amount greater than zero.', 'Enter a day from 1 to 31.', 'Choose an income category.'. Use `parseAmount` from money.js. Name 1 to 40 characters after trim.
- `addIncomeSource(data, value, now)`: checks `canAddIncomeSource`, pushes `{ id: createId('incsrc'), ...value, startDate: todayISO(now), skippedMonths: [] }`, returns `{ ok: true, source }` or `{ ok: false, reason }`. `updateIncomeSource(data, id, value)` replaces name, amount, day and category and keeps `startDate` and `skippedMonths`; `deleteIncomeSource(data, id)` removes the source and leaves its entries (their `sourceId` then points nowhere, which every function here treats as no source); `skipIncomeMonth(data, id, monthKey)` adds the month once. All return false or `{ ok: false }` for an unknown id.
- Confirming a payday is C-036 (`confirmIncome`, in this same file); the next payday and the per-day amount are C-038.

Changes apply from the current month on (decision 12): editing a source's amount or day changes what is expected from now on; entries already made, and the months they sit in, never change because status is always read from the entries.
