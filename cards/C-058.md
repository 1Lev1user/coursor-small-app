## Goal
A bank that shows spending as positive numbers and income as negative ones can be imported correctly: the Columns step has a "Reverse money in and out" checkbox that flips the direction of every row, is remembered with the saved bank layout, and is mentioned by the one-direction warning of the check panel. Today there is no way to reverse signs anywhere in the wizard.

## Notes
Source: D-bank.md problem 2, related case E7 (a bank showing expenses as positive and income as negative gives exactly the opposite, "no reverse signs option anywhere in the Columns step"), VERIFIED; fix shape (b) in the research. Depends on C-057 because it extends that panel's warning text and edits the same render function.

Design:
- `rowsToStatement` (text.js:766-870): when `layout.reverse === true`, flip the final `direction` ('in' <-> 'out') after it was read from the sign, the direction column or the split columns. Amount stays the absolute value.
- `state.layout.reverse` (boolean, default false) in startTable (src/views/import.js:567-572); `parseLayout()` (:603-618) passes `reverse` only when `mode === 'single'`.
- Checkbox with the existing `checkRow` helper (:403): label "Reverse money in and out", hint "Use this if your bank shows spending as positive numbers." Place it after the Direction select (:874-876).
- `layoutRecord` (:199-220): add `reverse: true` to the record ONLY when true (the existing test at importUi.test.js:100 checks keys of the record; absent means false). The saved-layout restore in startTable (:583-591) sets `reverse: saved.reverse === true`.
- C-057's `oneDirection` warning text gets one more sentence: "Try Reverse money in and out below."

Data format: `reverse` is an optional field of a bankLayouts record, absence means false, so backups and layouts from older versions load unchanged. AGENTS.md asks for a SCHEMA_VERSION step on a data format change; the planner's reading is that an optional field with a default is not one. Reviewer to confirm; if not, the fix is one MIGRATIONS step in src/model.js (outside this card's paths: stop and tell the owner).

Regression tests (new file, synthetic):
1. The failing input from the research (case E7), unsigned-sign-reversed bank, semicolon file, layout `{ columns: { date: 0, description: 1, amount: 2, ... }, decimalSeparator: ',', dateFormat: 'DMY' }`:
   `Datums;Apraksts;Summa` / `13.09.2026;RIMI;12,50` / `14.09.2026;ALGA;-900,00`.
   Without reverse: RIMI 'in', ALGA 'out' (what happens today). With `reverse: true`: RIMI 'out' 1250, ALGA 'in' 90000.
2. With a direction column `D`/`K` and `reverse: true`: D row becomes 'in', K row 'out'.
3. Split debit/credit layout with `reverse: true`: no flip applied by `parseLayout` logic (assert on the layout passed when mode is 'split').
4. `layoutRecord({ ..., layout: { mode: 'single', reverse: true, columns, decimalSeparator: ',', dateFormat: 'DMY' } }).reverse === true`; without the flag the record has no `reverse` property (`Object.hasOwn` false).
5. `layoutFitsSample` is unaffected by `reverse`.
