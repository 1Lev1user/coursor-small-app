## Goal
Fix the five CSS defects found by the 3.0 design review (owner decision 30) and add a test that stops a broken rule from silently dropping the next one again.

## Acceptance
- `node --test test/cssRules.test.js` exits 0
- `npm test` exits 0
- Manual (design-review): Month with a Savings category and a goal, Home after adding an expense (toast visible), a disabled button (Home review "Add to Savings" when already added) and keyboard focus on the Update bar button and on a primary button on a card, at 390, 768 and 1280 px, light and dark
- Manual (owner): on the iPhone, tap a secondary button and then tap elsewhere: the button does not stay in its hover colour

## Notes
Source: research/3.0/design-impeccable.md section 5 items 1, 2, 10; design-apple.md section 0 items 1-2; design-frontend.md section 0 item 3. Line numbers from main at 6788db8; verify.

1. Savings bar colour. style.css:577-587: the selector line `.progress-fill.is-savings {` is missing before `    background: var(--savings);\n}`. The orphan text becomes part of the next selector, so `.progress-fill.is-track-only` is dropped too (measured: both fills render pine). Restore the selector line.
2. Toast over the tab bar. `.toast` (:916-930) uses `bottom: calc(var(--tabbar-height) + var(--s4) + env(safe-area-inset-bottom))`, but the tab bar sits 1.6rem higher because of the rights strip (measured 10 px overlap at 390 px). Add `+ 1.6rem` exactly as `.update-bar` does at :1546.
3. Sticky hover on iPhone. Wrap every rule whose selector contains `:hover` (:307, :716, :862, :871, :880, :890, :1077, :1230, :1593, :1775, :1895 and any others found by search) in `@media (hover: hover) and (pointer: fine) { ... }`. Group adjacent ones into one media block where the order allows.
4. Disabled style. New tokens in the light `:root`: `--btn-off: #D3DBCF; --btn-off-ink: #56635B;` and in the dark block `--btn-off: #2E3A33; --btn-off-ink: #7F8C84;`. Rule:
   ```css
   .btn:disabled, .btn[aria-disabled='true'] {
       background: var(--btn-off);
       color: var(--btn-off-ink);
       cursor: not-allowed;
       transform: none;
   }
   ```
   Place this rule after `.update-bar .btn-primary` (:1559-1563), so it comes after every `.btn` hover, active and context rule it must beat (`.update-bar .btn-primary` would otherwise override the disabled Update button). Buttons that are disabled today: add.js:370 (savings), import.js:947 and :1442, app.js:542 (all `btn btn-primary`).
5. Focus ring visible on pine. Add `--focus: var(--accent);` to `:root` (both themes inherit it), change `:focus-visible` (:194) to `outline: 3px solid var(--focus)`, and set `--focus: #FFFFFF` on the pine surfaces `.home-figure` and `.update-bar` only. Not on `.btn-primary`: its ring is drawn outside the button, on the light surface, where white would vanish; there the pine ring stays. White on pine is 7.85:1; pine on pine today is 1:1.
6. Test `test/cssRules.test.js` reads style.css as text (same technique as test/contrast.test.js), strips `/* */` comments and asserts:
   - no stray text between two closing braces: every match of `/\}([^{}]*)\}/g` has only whitespace in its group, and the counts of `{` and `}` are equal (this catches item 1; a check of the text between `}` and the next `{` does not, because the orphan sits between two `}`);
   - a self-test: the same check run on an inline string reproducing the old bug (`.a{x:1}\n background: var(--savings);\n}\n.b{y:2}`) finds the stray text;
   - parse the rules with a small brace walker (selector prelude, body, ancestor preludes): a rule whose selector list includes `.progress-fill.is-savings` has `var(--savings)` in its body, and a rule for `.progress-fill.is-track-only` exists;
   - every rule whose selector contains `:hover` has an ancestor `@media (hover: hover)` block, and at least 11 such rules are seen (so the check is not vacuous);
   - `.btn:disabled` exists and `:focus-visible` uses `var(--focus)`;
   - the `.toast` `bottom` value contains `1.6rem`.
