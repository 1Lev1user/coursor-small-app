## Goal
One test file proves the whole import works for every format the research found, from file bytes to `buildImport`:
- Citadele .xls (the existing fixture);
- Revolut CSV; Swedbank LV, EE and LT CSV; SEB LT CSV; LHV CSV with BOM; Wise CSV; N26 CSV;
- camt.053 with a reversal pair and a batch;
- FiDAViSTA;
- an HTML ".xls" and a SpreadsheetML ".xls";
- a windows-1257 CSV and a windows-1251 CSV.

For each format: the expected row count, money in and money out, and no unexpected skipped rows. This is the acceptance test of slice 4.

## Acceptance
- `node --test test/importFormatMatrix.test.js` exits 0
- `node --test test/importFormatMatrix.test.js 2>&1 | grep -E '^# pass ([9]|[1-9][0-9])'` exits 0
- `npm test` exits 0

## Do not touch
- existing test files
- every src/ file: this card only adds tests and fixtures. If a format fails, report it with the exact failing assertion; the fix becomes a new card.

## Notes
- Fixtures are written fresh with made-up names, IBANs and amounts, in the shapes of research/3.1/bank-shapes.md. Never copy third-party files.
- Drive each file through `readStatementFile` (src/views/import.js, exported), then:
  - for tables: `findHeaderRow`, `guessColumns`, `rowsToStatement`, with no manual mapping;
  - for XML: the parser result;
  - then `defaultDecisions` and `buildImport` with a fixed `now`.
- Assert:
  - rows;
  - money in and money out;
  - kinds where the research defines them (Revolut TOPUP/EXCHANGE → transfer; camt reversal pair → skip);
  - skipped reasons.
