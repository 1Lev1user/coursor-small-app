## Goal
A CSV file that begins with 11 or more descriptive lines (account, period, bank name) before the header is read correctly. Today delimiter detection looks only at the first 20 non-empty lines, all four delimiters score 0, "," wins, the amounts are split on their decimal comma and the import yields 0 rows.

## Notes
Source: D-bank.md problem 7, first part (VERIFIED, probe p03_csv2.mjs "preamble loop": up to 10 preamble lines are fine; 11, 12 and 15 lines give 0 rows), NOT among the 8 claims re-checked in D-bank-verify.md; the planner re-ran the failing case against the current code instead (11, 12 and 15 preamble lines give delimiter ',' and 0 imported rows; 10 lines give ';' and 30 rows). How many preamble lines real exports carry is UNVERIFIED; the owner's sample file settles whether this ever happens.

Cause: `scoreDelimiter` (text.js:120-147) scores each candidate over `rows.slice(0, 20)` of the non-blank rows (:122). With 11 or more single-field preamble lines the header and data rows are mostly outside the sample, the dominant field count is 1 (below 2) and the score is 0 for all candidates.

Fix: score each delimiter on a window that starts one row above the first row holding a date-like cell (`isDateLikeValue`, text.js:281, applied to each trimmed cell), instead of always on rows 0-19: `const firstDate = rows.findIndex(...); const start = firstDate > 0 ? firstDate - 1 : 0; const sample = rows.slice(start, start + 20);`. Keep the rest of the formula (`consistency + dominantCount / 1000`, "dominant count under 2 scores 0"). Under a wrong delimiter (',' splitting "12,50") no cell is date-like, so that candidate keeps the old window and still scores 0 on a long preamble.
DO NOT drop single-field rows from the sample and score only multi-field rows: the planner tried that on a prototype and it breaks the existing preamble test (',' then scores 1.0 on the few rows whose decimal comma splits them and beats ';'). The windowed version above was prototyped against a copy of text.js: all 67 tests of importText.test.js pass and the cases below give ';' with the header at the expected index.

Regression tests (new file, synthetic, through `parseDelimited` then `findHeaderRow`):
1. The failing input from the research: 11 preamble lines without any delimiter (`Bank statement line 1` ... `line 11`), then `Datums;Apraksts;Summa;Valuta` and 30 rows `13.09.2026;S0;-12,50;EUR` (S0..S29). EXPECTED: delimiter ';', `rows.length === 42`, `findHeaderRow(rows) === 11`. ACTUAL before: delimiter ',', 0 usable rows.
2. The same with 12 and 15 preamble lines (before: 0 rows).
3. 25 preamble lines of the `key;value` kind (2 fields): ';' with the 4-field table still wins and `findHeaderRow` finds the header (index 25). Also 25 and 40 plain preamble lines (expected header index 25 and 40; with 40 preamble lines and only 5 data rows ';' still wins).
4. 10 preamble lines and 0 preamble lines still work (controls; header index 10 and 0).
5. Tab-separated text with 15 plain preamble lines then 3 rows `17.09.2026\tCoffee Shop\t-4,50\tEUR`: delimiter '\t'.
6. Comma-delimited file (`Started Date,Completed Date,Description,Amount,Currency`, amounts with dot decimals) after 12 plain preamble lines: delimiter ','.

Second case, from the C-060 review (PR #27): since C-060 a `"` opens a quoted field only at the start of a field, so a headerless, all-quoted file whose every row has the same number of commas inside the quoted fields now ties ',' with ';' in `scoreDelimiter` and ',' wins by order. Example: 25 rows of `"13.04.2026";"Shop, N";"-N,50"` with no header gives ',' and broken fields; on the base before C-060 it gave ';'. Add a test for this file (expect ';' and 3 fields per row) and fix the tie in `scoreDelimiter`, for example by preferring the candidate whose fields are all fully quoted, or the candidate that splits outside quotes. Keep every existing importText case green. One more C-060 side effect to keep in mind, no change needed unless a real file shows it: an Excel text formula `="001"` now keeps its quotes.
