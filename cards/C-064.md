## Goal
CSV and Excel files that carry a status per row (Revolut-style: COMPLETED, PENDING, REVERSED, DECLINED) no longer import rows that were not completed as real spending. The Columns step gets an optional "Status" column; rows whose status is one of the known not-completed words are listed under skipped lines with a clear reason. Today PENDING and REVERSED card payments are imported as ordinary expenses.

Relation to decision 23 (research/3.0/decisions-3.0.md: a camt reversal is imported as a refund, card C-066): that decision is about camt only. A REVERSED row in a CSV stays skipped here, because the CSV shape is assumed and the file may list the money back as a separate line. If the owner's sample shows a REVERSED row that is the only trace of the money coming back, revisit this rule with the owner before the card is finished.

Design:
- New optional column key `status`. `guessColumns` (text.js:336-489): a header is the status column when, after normalisation (case, diacritics), it EQUALS `status`, `state`, `statuss` or `статус`, or starts with `status ` (exact match on purpose: "Statement details" contains "state" and must not match). Add the category to `CATEGORY_ORDER` (:265) at the end. Set `columns.status` only when found (do NOT add `status: -1` to `emptyColumns()` :267, the existing deepEqual test would fail). In startTable (src/views/import.js:563) add `status: -1` to the UI copy next to `eurAmount: -1`.
- `rowsToStatement` (text.js:766-870): after the summary and date checks, when `columns.status >= 0` and the normalised cell is in `SKIP_STATUSES` = PENDING, REVERSED, DECLINED, FAILED, CANCELLED, CANCELED, REJECTED, REZERVETS (Rezervēts; diacritics stripped), skip the row with reason 'not completed'. Known words only: any other value (COMPLETED, empty, "Izpildīts") imports as before.
- `SKIP_REASONS` (import.js:46-50): `'not completed': 'Not completed (pending, reversed or declined)'`.
- Columns step (import.js:860-881): `columnSelect(ctx, 'status', 'Status (optional)', true, 'Rows marked pending, reversed or declined are skipped.')`, after the Bank reference select.
- Saved layouts (startTable :583-591 merges `{ ...state.layout.columns, ...saved.columns }`): a guessed `status` column IS inherited by a saved layout that has none, because it can only skip not-completed rows (safe). The column is stored in the layout record automatically (`layoutRecord` spreads `layout.columns`, import.js:199).

Regression tests (new file, synthetic; header and rows as above, `parseDelimited` -> `findHeaderRow` -> `guessColumns` -> `rowsToStatement`):
1. The failing input from the research: with the three rows above plus the EXCHANGE row `EXCHANGE,Current,2026-09-18 09:00:00,2026-09-18 09:00:00,Exchanged to USD,-100.00,1.50,EUR,COMPLETED,886.00`. EXPECTED: guessColumns finds `status` at index 8; imported rows are CAFE (300) and the exchange row (10000); AMAZON and SHOP X are skipped with reason 'not completed'. ACTUAL before: AMAZON 2000 and SHOP X 800 imported.
2. Matching is case- and diacritics-insensitive (`pending`, `Rezervēts`).
3. Unknown status values (`COMPLETED`, `Izpildīts`, empty cell) import normally.
4. A file with no status header: `guessColumns(...).columns` has no `status` key (Object.hasOwn false) and the importText.test.js deepEqual still passes.
5. A saved layout without `status` applied to this file still skips PENDING rows: extract the merge at import.js:584 into a small exported helper `mergeSavedColumns(guessedColumns, savedColumns)` and test that `status` from the guess survives while the saved keys win.
6. A header named "Statement details" (or "Statement") is not taken as the status column.
