## Goal
In Settings > Categories each category is one short row (name, limit, subcategory count); tapping a row opens its buttons and subcategories, one category at a time. The list shrinks from about 2,500 px to under 400 px, and the Rename and Delete buttons of a subcategory stay on one line.

## Acceptance
- `node --test test/categoryRows.test.js` exits 0
- `npm test` exits 0
- Manual (design-review): Settings > Categories with all rows collapsed, one category open (with 6 subcategories), and the Edit-limit form open, at 390, 768 and 1280 px, light and dark; at 390 px each subcategory row is one line; all buttons at least 44 px high; owner checks
- Manual (owner): with the default data the Categories group shows four short rows; open Necessary, rename a subcategory, delete one, add one; the row stays open after each; opening another category closes the first; Home > month review "Review categories" lands on the group

## Do not touch
- SCHEMA_VERSION and MIGRATIONS
- Category data and plan logic (src/budget.js, src/model.js)
- The Add category form (a later card adds a notice to it)
- existing test files
- Limit for `src/views/settings/shared.js`: one new field in `state` (`openCategoryId: null`); do not reset it in `closeTransientUi`.
- Limit for `style.css`: `.more-category*` and `.subcategory-*` rules, tokens only.

## Notes
Source: C3 F8 and F17 (screenshots c3-09-settings-phone-chip-categories.png, c3-38): Categories is about 2,500 px of the page and each subcategory takes about 123 px because "Delete" wraps to its own line. Line numbers are from `main-work` at 05d1355; verify before editing.

`src/views/settings/categories.js` `renderCategory` (:325-407) today always renders: head (name + `shareLabel`), the Edit/Rename/Delete buttons, the subcategory list and the add-subcategory form.
- New collapsed row: the head becomes `<h3 class="category-name-row"><button type="button" class="more-category-toggle" aria-expanded aria-controls>` with the name, a muted second line `<shareLabel> · <subcategoryCountText>` and a chevron (same look as `.settings-row` from C-041; reuse its rules by adding the class `settings-row` and a modifier instead of copying CSS).
- Export a pure helper `subcategoryCountText(count)`: `No subcategories` for 0, `1 subcategory`, `N subcategories`.
- Open state: `state.openCategoryId` (add to `state` in shared.js:11-43, default null). Tap sets it to the id or null; `closeTransientUi()` must not touch it, so edit forms keep their category open. A category is rendered open when `state.openCategoryId === category.id` OR one of `state.renameCategoryId`, `state.editPlanCategoryId`, `state.confirmCategoryId`, `state.renameSubKey` / `state.confirmSubKey` (key prefix `<category id>:`) points at it, so a form is never hidden. After a toggle set `state.focusId` to the toggle button id so focus stays on the row.
- Open body: the existing action buttons (`Limit`, `Rename`, `Delete`; names as set by C-040), the existing subcategory list and add-subcategory form, unchanged.
- Subcategory row (`renderSubcategory` :241-292): one line. CSS in style.css: `.subcategory-item` (:1126-1136) `flex-wrap: nowrap`; `.subcategory-name` (:1143-1147) `flex: 1 1 0; min-width: 0; overflow-wrap: anywhere`; the two buttons `flex: none`. At 390 px the card content is about 326 px: name about 100 px, two ghost buttons about 80 px each fit (unverified; if they do not, shorten the buttons' side padding, do not drop the 44 px height).
- The `Subscriptions` category stays out of this list (categories.js:50-58, it lives in the Subscriptions group).

Tests, new `test/categoryRows.test.js`: `subcategoryCountText` for 0, 1, 2; `state.openCategoryId === null` by default and unchanged after `closeTransientUi()` (import `state`, `closeTransientUi` from `../src/views/settings/shared.js`, same technique as test/preUpdateConfirmState.test.js); `shareLabel` is not changed (do not test it here).

Open: whether Rename and Delete for a subcategory should move behind a "..." menu (C3 suggestion) is not decided; this card keeps both visible buttons.
