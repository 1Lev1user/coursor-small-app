## Goal
Two changes to what the Duplicates step decides on its own, both about rows that only look like something already saved:
1. A genuinely new payment that happens to reuse a bank reference (a top-up reference, a camt running number "1", "2") is no longer marked "Exact: already imported" and left out silently when its date and text differ from the stored entry. Today reference + direction + amount within 5 days is enough.
2. Rows that only look like an already saved entry (same amount within 2 days, or the same date and amount as an entry the person typed) start unticked and are labelled "Possible duplicate" (owner decision 22). Today the "Weak" rows start ticked, so a CSV imported first and the camt of the same period afterwards double every row unless each one is unticked by hand.

Part 1.
Cause: `byReference` (src/import/core.js:105-113) accepts a stored entry with the same `direction|bankRef` when the amount matches and `|days| <= 5`, ignoring the text.
Fix: a reference match is Exact only when at least one holds: (a) the dates are at most 1 day apart (booking versus value date); (b) the row's normalised text (`rowText(row)`, :36) equals the stored entry's text, taken from the tail of its stored `fingerprint` (format `date|amountKey|direction|text`, optionally followed by `#n`; the text may itself contain `|`, split at the third `|` only); (c) the reference is "strong": at least 12 characters and not purely digits (a bank transaction id such as `RF2026091400001`); strong references keep the 5-day window. Otherwise fall through to the existing probable, weak and ignored checks, so the row can still be reported Weak when the amount is within 2 days. The stored fingerprint of older entries may be unparseable (test fixtures use 'x' or 'fp-aug'): then rule (b) simply does not apply.
The rule was prototyped by the planner on a copy of core.js: all 30 tests of importCore.test.js pass and cases 1-5 of the first test file give the stated levels (case 1 null, 2 exact, 3 exact, 4 exact then null, 5 null then exact; the +2 days different-text row is 'weak').

Part 2.
- `defaultDecisions` (core.js:354-369): `include` is true only when the row has no duplicate level at all (`!duplicates[index]?.level`); today it is `level !== 'exact' && level !== 'probable'`, which leaves 'weak' ticked. Exact (including rows matched as "ignored" from an earlier import) and Probable stay unticked as today.
- `DUPLICATE_GROUPS` (import.js:52-56) is exported (the test reads it) and relabelled: `['exact', 'Exact', 'Already imported. The bank reference or every detail matches.']` unchanged; `['probable', 'Possible duplicate: added by you', 'Same date and amount as an entry you added yourself. Not imported unless you tick it.']`; `['weak', 'Possible duplicate: similar amount', 'Same amount within 2 days of a saved entry. Not imported unless you tick it.']`. The checkbox label stays "Import anyway", which is now correct because every duplicate row starts unticked. The groups keep their order (exact, probable, weak).
