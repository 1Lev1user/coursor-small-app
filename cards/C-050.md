## Goal
Switching tabs (and opening an Add form from Home) always starts at the top of the new screen instead of keeping the old scroll position, and the Add expense and Add income forms put the cursor in the first field and go back to Home on Escape, with a visible focus ring on the date picker.

## Acceptance
- `node --test test/screenFocus.test.js` exits 0
- `npm test` exits 0
- Manual (design-review): Add expense with the Category select focused on open, and the date field focused by keyboard (visible 3 px ring on the picker button), at 390, 768 and 1280 px, light and dark; owner checks
- Manual (owner): scroll Settings to the bottom, tap Month: Month starts at the top with the totals visible; scroll Home down, tap Add expense: the form starts at the top and the Category select has focus; press Escape: back on Home with the typed amount still in the form when you reopen it; Home > month review "Review categories" still opens and scrolls to the "Categories and limits" group of Settings (C-041)

## Do not touch
- SCHEMA_VERSION and MIGRATIONS
- Month navigation (`setMonthKey`) and any re-render caused by saving: scroll and focus must not move on those
- The Month search panel and the import wizard (their focus handling stays)
- existing test files
- Limit for `src/app.js`: `goTo` (:104-118) only.
- Limit for `style.css`: one rule for the date picker indicator focus ring, tokens only.

`src/app.js` `goTo` (:104-118; its title use is at :494): remember `const changed = tab !== app.tab;` and, when `changed`, call `window.scrollTo(0, 0)` after `app.tab = tab` and before `render()`. The Settings deep link (`openSettingsSection`, src/views/more.js:18-20) sets its smooth scroll inside `render`, which runs after this, so it still wins. Do not scroll in `render()` itself: every save re-renders.

`src/views/add.js`:
- `openAddPanel(next)` (:87-108): note the previous `panel`. When `next` is `'expense'` or `'income'` and differs from the previous panel, set a module flag `focusFormRequested = true` and, when `typeof window !== 'undefined'`, call `window.scrollTo(0, 0)`. Export `takeFocusRequest()` that returns the flag and clears it.
- `renderExpenseForm` end (:1566-1581) and `renderIncomeForm` end (:996-999): call `takeFocusRequest()` once, unconditionally, and use it only as the last `else if` after the existing branches (`focusSaveErrorOnRender`, `addingCategory`, `focusAmountOnRender`, `addingIncomeCategory`): focus `categorySelect` (expense form) or the select with id `home-income-category` (income form). A re-render caused by validation or a quick panel must not steal focus, which the "differs from the previous panel" rule guarantees. The save-failure path calls `openAddPanel('expense')` while the panel is `'added'` (:1521); its error focus already takes precedence.
- Export a pure `escapeAction(event, quickPanelOpen)`: returns `null` unless `event.key === 'Escape'` and the event is not `defaultPrevented` and not `isComposing`; then `'close-panel'` when `quickPanelOpen` is true, otherwise `'home'`. Attach one `keydown` listener to each of the two forms (`form` created with `document.createElement('form')` at :1028 in `renderExpenseForm` and at :721 in `renderIncomeForm`): for `'close-panel'` call the existing `closeQuickPanels()` and `ctx.render()`; for `'home'` call `openAddPanel('home')` and `ctx.render()`; call `event.preventDefault()` in both cases. `quickPanelOpen` is `addingCategory || confirmNoteAsSub || addingIncomeCategory`. The module-level `draft` and `incomeDraft` survive, so Escape loses no typed text.
- `style.css`: near `.field input[type='date']` (:805-810) add `.field input[type='date']::-webkit-calendar-picker-indicator:focus-visible { outline: 3px solid var(--accent); outline-offset: 2px; border-radius: var(--radius-sm); }`. The pseudo-element is Chromium and Safari only; Firefox draws its own ring (unverified).

Tests, new `test/screenFocus.test.js` (import `openAddPanel`, `takeFocusRequest`, `escapeAction` from `../src/views/add.js`; no DOM is needed): after `openAddPanel('home')` the request is false; `openAddPanel('expense')` then `takeFocusRequest()` is true and the next call false; opening `'expense'` again while already on it gives false; `openAddPanel('income')` from `'expense'` gives true; `openAddPanel('added')` and `('home')` give false; `escapeAction({ key: 'Escape' }, false)` is `'home'`, with `true` it is `'close-panel'`, `{ key: 'a' }` and `{ key: 'Escape', defaultPrevented: true }` are `null`.
