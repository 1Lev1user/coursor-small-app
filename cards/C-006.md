## Goal
Publish workflow: v1 updated only after npm test passes.

## Acceptance
- `node --test test/publishWorkflow.test.js` exits 0
- `node --test test/publishWorkflow.test.js 2>&1 | grep -E '^# pass ([4-9]|[1-9][0-9])'` exits 0
- `grep -c 'needs: test' .github/workflows/publish.yml` prints 1 or more
- `npm test` exits 0
- Manual (owner): a push to main whose npm test fails leaves `git ls-remote origin v1` unchanged
- Manual (owner): a green push to main with a raised version pair: v1 gets one commit 'Release <version>' and the live site shows the Update bar

## Do not touch
- .github/workflows/test.yml
- .github/workflows/board-sync.yml
- src/
- sw.js
- package.json
- force push or history rewrite
- secrets other than GITHUB_TOKEN
- pushing to v1 from the agent session

## Notes
Decision A2: publish automatically on every push to main, after npm test passes (workflow_dispatch stays for a manual rerun). on: push branches [main] and workflow_dispatch; top-level permissions contents: read. Job test: checkout, setup-node 22, npm test. Job publish: needs: test; permissions contents: write; concurrency group publish-v1; checkout fetch-depth 0; if sw.js VERSION on the source commit equals VERSION in origin/v1:sw.js, end the job with a notice and publish nothing (most pushes to main are not releases); build the tree from scripts/ship-files.txt in a worktree of v1 (delete files not listed, copy listed ones), commit as github-actions[bot] 'Release <package.json version>', `git push origin HEAD:v1` without --force. Today v1 is updated by hand (3009017 'Release 2.0.0') and test.yml (on push/PR) gates nothing. Test reads the yml text and asserts: push to main; workflow_dispatch; a job runs `npm test`; `needs: test`; `contents: write`; reads scripts/ship-files.txt; pushes to v1; no '--force'; no 'secrets.' other than GITHUB_TOKEN. Pages stays 'deploy from branch v1'.
