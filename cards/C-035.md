## Goal
The "Subscription due" screen no longer asks about a subscription the owner already paid (typed, or imported from the bank), and it offers Later and Skip this month besides Confirm and Delete.

## Notes
Problems seen in the running app: the screen cannot be dismissed (Escape and a tap on the backdrop do nothing, app.js:339-343 and :396-400 only close the delete confirm); Delete sits next to Confirm with the same size (app.js:374-383); a Spotify bank row imported on 4 Oct is not linked to the subscription, so on 6 Oct the app asks again and Confirm creates a second charge (`isLoggedThisMonth` only knows `subscriptionId`, subscriptions.js:16-21; imported expenses never get one); after "Import backup > Settings only" the screen appears at once for every subscription.

subscriptions.js:
- New `matchesSubscription(expense, subscription)`: normalise by lower-casing, removing diacritics (`normalize('NFD')` and delete `\p{M}`), and turning every run of characters that are not letters or digits into one space. True when the normalised `subscription.name` appears as whole words inside the normalised `note + ' ' + bankText` of the expense (compare ` ${text} ` with ` ${name} `), the expense is not a refund, and `Math.abs(expense.amountCents - subscription.amountCents) <= Math.max(100, Math.round(subscription.amountCents * 0.25))` (a small price change still matches; "Gym" does not match a 79.00 "Gym shoes" row when the subscription is 39.00).
- New `isPaidThisMonth(data, subscription, monthKey)` = `isLoggedThisMonth(data, subscription.id, monthKey)` or any expense dated in that month for which `matchesSubscription` is true.
- `dueSubscriptions` (:29-41): use `isPaidThisMonth` instead of `isLoggedThisMonth`, and drop a subscription whose `skippedMonths` (missing means none) contains `monthKey`.
- New `skipSubscriptionMonth(data, subscriptionId, monthKey)`: adds the key once, returns true; false for an unknown id.

app.js due screen:
- Actions in this order: Confirm (primary, as today), Later, Skip this month, then Delete subscription demoted to `btn btn-ghost-danger` (the Settings list already uses that class, settings/subscriptions.js:316). Keep the delete confirm box as it is.
- Later: remember `${subscription.id}:${monthKey}` in a module-level `Set` named `postponedDue` and render again; the screen for that subscription does not return until the page is reloaded. `render()` (:509-515) filters `dueSubscriptions(app.data)` through the set. Escape, and a click on the dark backdrop (`event.target === overlay`), do the same as Later; in the delete confirm Escape still only cancels the confirm (`attachDueTrap`, :251-277).
- Skip this month: `skipSubscriptionMonth`, then `save()`; on a failed save (returns false) undo the push and keep the screen; on success toast 'Skipped for this month'.
- Add one comment where `postponedDue` is declared: C-036 reuses it for income reminders.

test/subscriptionReminder.test.js (new, fixed `now`) must assert: (1) a Spotify subscription (name 'Spotify', 1199, day 5), an imported expense `note: 'Spotify AB'`, `bankText: 'SPOTIFY AB STOCKHOLM'`, 1199, dated 2026-10-04, `now` 6 Oct 2026: not due; (2) the same expense for 2026-09-04 does not stop the October reminder; (3) amount 5000 with the same note does not match; (4) name match ignores case and diacritics ('Rīgas satiksme' vs 'RIGAS SATIKSME 12'); (5) 'Gym' does not match 'Gymnastics club' (whole words only); (6) a refund row does not match; (7) `skipSubscriptionMonth` hides the reminder for that month and shows it again on 1 Nov; (8) a subscription object without `skippedMonths` still works (old test shape).

Unverified: the 25 % amount tolerance and whole-word name match are a proposal (owner decision in _index). Nothing links an old unmatched row after the fact; a row typed with a different name will still prompt, and the owner uses Skip this month.
