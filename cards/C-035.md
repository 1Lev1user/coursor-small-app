## Goal
A subscription row in a bank import is never matched silently: the import asks "Is this the Spotify subscription?" and the owner answers Yes or No; Yes marks the charge as the subscription's payment for that month, so its reminder stops. The "Subscription due" screen also offers Later and Skip this month.

## Notes
Owner decisions (research/3.0/decisions-3.0.md): 11 a subscription paid via bank import: the import suggests "Is this the Spotify subscription?"; Yes marks it paid and the reminder stops. The task text adds: no automatic match, the user confirms. So there is no amount tolerance and no silent linking; the amount of the bank row is not looked at.

Problems seen in the running app: the screen cannot be dismissed (Escape and a tap on the backdrop do nothing, app.js:339-343 and :396-400 only close the delete confirm); Delete sits next to Confirm with the same size (app.js:374-383); a Spotify bank row imported on 4 Oct is not linked to the subscription, so on 6 Oct the app asks again and Confirm creates a second charge (`isLoggedThisMonth` only knows `subscriptionId`, subscriptions.js:16-21; imported expenses never get one); after "Import backup > Settings only" the screen appears at once for every subscription.

subscriptions.js:
- New `nameAppearsIn(name, text)`: normalise both by lower-casing, removing diacritics (`normalize('NFD')` and delete `\p{M}`), and turning every run of characters that are not letters or digits into one space; true when the normalised name, padded with spaces, appears inside the normalised text padded with spaces (whole words only: 'Gym' is not in 'Gymnastics club'). An empty name never matches.
- `dueSubscriptions` (:29-41): also drop a subscription whose `skippedMonths` (missing means none) contains `monthKey`. `isLoggedThisMonth` is unchanged, so an imported expense that carries the subscription's id stops the reminder.
- New `skipSubscriptionMonth(data, subscriptionId, monthKey)`: adds the key once, returns true; false for an unknown id.

import.js (the question):
- `export function suggestSubscription(data, row, decision, takenKeys = new Set())` next to `suggestSalary`: returns the first subscription of `data.subscriptions` for which all hold: `decision.kind === 'expense'`, `row.direction === 'out'`, `decision.subscriptionId` is empty and `decision.subscriptionDeclined` is not true, `nameAppearsIn(subscription.name, [row.counterparty, row.description].join(' '))`, `isLoggedThisMonth(data, subscription.id, monthKeyOf(row.date))` is false, and `${subscription.id}:${monthKeyOf(row.date)}` is not in `takenKeys` (the keys of other rows of the same import already answered Yes, so a month is asked once). Otherwise null.
- In `renderDecisionRow`, for an expense row: when `suggestSubscription(...)` returns a subscription show a muted `imp-hint` line `Is this the ${name} subscription?` with two small buttons Yes and No. Yes sets `decision.subscriptionId = subscription.id` and re-renders the row; the row then reads `Marked as the ${name} subscription for ${monthLabel(monthKey)}.` with an Undo button that clears it. No sets `decision.subscriptionDeclined = true` and the question disappears. Yes does not change the category or anything else the owner chose. `copyChoice` (:127) does not copy these two fields, so "Apply to all" never answers the question for other rows.

core.js (:522-529): in the expense branch, when `decision.kind === 'expense'` and `decision.subscriptionId` is a non-empty string that equals the id of a subscription in `data.subscriptions`, add `subscriptionId: decision.subscriptionId` to the built expense; otherwise the expense keeps exactly the keys it has today. The import record, undo and duplicate logic are unchanged (undoing the import removes the expense, so the reminder returns).

app.js due screen:
- Actions in this order: Confirm (primary, as today), Later, Skip this month, then Delete subscription demoted to `btn btn-ghost-danger` (the Settings list already uses that class, settings/subscriptions.js:317). Keep the delete confirm box as it is.
- Later: remember `${subscription.id}:${monthKey}` in a module-level `Set` named `postponedDue` and render again; the screen for that subscription does not return until the page is reloaded. `render()` (:509-515) filters `dueSubscriptions(app.data)` through the set. Escape, and a click on the dark backdrop (`event.target === overlay`), do the same as Later; in the delete confirm Escape still only cancels the confirm (`attachDueTrap`, :251-277).
- Skip this month: `skipSubscriptionMonth`, then `save()`; on a failed save (returns false) undo the push and keep the screen; on success toast 'Skipped for this month'.

test/subscriptionReminder.test.js (new, fixed `now`; build rows like test/importUi.test.js and decisions like test/importCore.test.js) must assert: (1) `dueSubscriptions` with `now` 6 Oct 2026 lists a subscription (Spotify, 1199, day 5) that has no expense; an expense with its `subscriptionId` dated 2026-10-04 removes it; the same expense dated 2026-09-04 does not; (2) `skipSubscriptionMonth` hides the reminder for that month, shows it again on 1 Nov, returns false for an unknown id; (3) a subscription object without `skippedMonths` still works (old test shape); (4) `nameAppearsIn('Spotify', 'SPOTIFY AB STOCKHOLM')` true, `nameAppearsIn('Rīgas satiksme', 'RIGAS SATIKSME 12')` true, `nameAppearsIn('Gym', 'Gymnastics club')` false, an empty name false; (5) `suggestSubscription` returns Spotify for an out row 'SPOTIFY AB' of 5000 (the amount differs from the subscription's 1199 and it still asks) in October, null once an expense tagged with the subscription id exists in October, null for a refund or a money-in row, null after `subscriptionDeclined`, null when `takenKeys` holds the key; (6) `buildImport` with `subscriptionId` on the decision creates an expense that carries it, after `applyImport` the October reminder is gone; an unknown id adds no field; a refund decision adds no field.

Not covered, on purpose: an old row imported before this card is not linked afterwards; the owner uses Skip this month. Income rows in the import are not tied to an income source (owner decision 4: only Add income and the payday reminder tie an income to a source); say so to the owner if a salary row from a statement leaves the payday reminder open.
