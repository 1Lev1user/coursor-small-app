## Goal
In Settings > Plan, changing the budget to 0 asks for a confirmation first, and edits that are typed but not saved are marked "Unsaved changes" with a Discard button, so a field that still shows 1234 after leaving Settings no longer looks like the saved plan.

## Acceptance
- `node --test test/planFormState.test.js` exits 0
- `npm test` exits 0
- Manual (design-review): Settings > Plan with the "Unsaved changes" marker, and with the zero-budget confirmation, at 390, 768 and 1280 px, light and dark; Discard and the confirm buttons at least 44 px high; owner checks
- Manual (owner): type 1234 in the budget, switch to Home and back: the field still shows 1234 and the marker reads "Unsaved changes"; Discard restores the saved value; type 0 and Save: the confirmation appears; Cancel keeps the old budget

## Do not touch
- SCHEMA_VERSION and MIGRATIONS
- Setup (src/views/setup.js, which allows a zero budget on purpose)
- `parseAmount` (a separate card changes it) and the plan calculations in src/budget.js
- existing test files
- Limit for `style.css`: one rule for the marker text, tokens only.

## Notes
Source: C3 F13 and F15 (screenshots c3-23-plan-invalid-budget.png; text dump: the budget field kept "1234" while the saved budget was 600). Budget 0 is accepted today and makes every expense "over budget"; a zero budget is still a legal state (Setup allows it, categories show "no budget"), so the card confirms instead of refusing. Line numbers are from `main-work` at 05d1355; verify before editing.

`src/views/settings/plan.js`:
- `planDraft` (:13-19) already survives re-renders and tab switches; keep that (no typed text is lost), and add `confirmZero: false`.
- Export `planDraftDirty(settings, draft)`: false when all three draft fields are null; otherwise true when the trimmed name differs from `settings.userName`, or the budget text differs from the saved budget, or the income text differs from the saved income. Compare money by cents when the text parses (`'1000'` equals saved 100000 cents, `'1000.00'` equals it too), and as text when it does not parse (`''` or `'abc'` is a change).
- Export `needsZeroBudgetConfirm(savedCents, newCents)`: true only when `savedCents > 0` and `newCents === 0`.
- Marker: `p.plan-unsaved` (`role="status"`, text `Unsaved changes`) plus a `Discard` button (`btn btn-ghost`, `type="button"`) placed above the Save button in `renderPlanSection` (:125-201). Toggle `hidden` live from the three `input` listeners (:141-168) by calling a local `syncDirty()`, also once at render. Discard sets the three draft fields to null, clears the error and calls `ctx.render()`. A successful save already nulls the draft (:114-118).
- Zero confirmation: in `savePlan` (:70-123), after the budget and income parse and when `needsZeroBudgetConfirm(ctx.data.settings.monthlyBudgetCents, budgetCents)` and `planDraft.confirmZero` is false, set `planDraft.confirmZero = true`, keep the draft and `ctx.render()`. The render then shows a group (`role="group"`, class `confirm-box`) with text `A budget of 0 makes every expense show as over budget. Save anyway?` and two buttons, `Cancel` (clears `confirmZero`) and `Save budget 0` (class `btn btn-danger`; sets `confirmZero` and runs the save again). Any edit to the budget input clears `confirmZero`. `renderConfirm` in shared.js:237-246 has a fixed `Delete` label, so build this box with `actionButton` and `element` from shared.js instead of changing it.
- CSS: `.plan-unsaved` colour `var(--muted)`, weight 600 (the marker must also be readable without colour: the words carry it).

Tests, new `test/planFormState.test.js` (import both helpers from `../src/views/settings/plan.js`): `planDraftDirty` with all-null draft (false), name `'Tess '` against saved `'Tess'` (false), budget `'1000'` against 100000 cents (false), `'1000.50'` (true), `''` against saved 100000 (true), income changed only (true); `needsZeroBudgetConfirm(100000, 0)` true, `(0, 0)` false, `(100000, 100)` false, `(0, 500)` false.
