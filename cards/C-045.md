## Goal
In Settings > Monthly budget, saving a budget of 0 is allowed but only after an "Are you sure?" step (owner decision 20), and edits that are typed but not saved are marked "Unsaved changes" with a Discard button, so a field that still shows 1234 after leaving Settings no longer looks like the saved budget.

## Acceptance
- `node --test test/planFormState.test.js` exits 0
- `npm test` exits 0
- Manual (design-review): Settings > Monthly budget with the "Unsaved changes" marker, and with the "Are you sure?" confirmation, at 390, 768 and 1280 px, light and dark; Discard and the confirm buttons have a tap target of at least 44 px; owner checks
- Manual (owner): type 1234 in the budget, switch to Home and back to Settings > Monthly budget: the field still shows 1234 and the marker reads "Unsaved changes"; Discard restores the saved value; type 0 and Save: "Are you sure?" appears; Cancel keeps the old budget; "Save budget 0" saves 0

`src/views/settings/plan.js` after C-041 (the Monthly budget form holds the budget field and, until C-034 changes it, the usual-income field; the name lives in `renderProfileSection`):
- `planDraft` (:13-19 before C-041) already survives re-renders, tab switches and a collapsed group; keep that (no typed text is lost), and add `confirmZero: false`.
- Export `planDraftDirty(settings, draft)`: false when the budget and income draft fields are null (or missing); otherwise true when the budget text differs from the saved budget, or the income text differs from the saved income. Compare money by cents when the text parses (`'1000'` equals saved 100000 cents, `'1000.00'` equals it too), and as text when it does not parse (`''` or `'abc'` is a change). Draft fields that are null or undefined count as unchanged, so the function keeps working if C-034 removes the income field.
- Export `needsZeroBudgetConfirm(savedCents, newCents)`: true only when `savedCents > 0` and `newCents === 0`.
- Marker: `p.plan-unsaved` (`role="status"`, text `Unsaved changes`) plus a `Discard` button (`btn btn-ghost`, `type="button"`) placed above the Save button in `renderPlanSection`. Toggle `hidden` live from the `input` listeners by calling a local `syncDirty()`, also once at render. Discard sets the draft fields to null, clears the error and calls `ctx.render()`. A successful save already nulls the draft.
- Zero confirmation: in `savePlan`, after the budget parses and when `needsZeroBudgetConfirm(ctx.data.settings.monthlyBudgetCents, budgetCents)` and `planDraft.confirmZero` is false, set `planDraft.confirmZero = true`, keep the draft and `ctx.render()`. The render then shows a group (`role="group"`, class `confirm-box`) with text `Are you sure? A budget of 0 makes every expense show as over budget.` and two buttons, `Cancel` (clears `confirmZero`) and `Save budget 0` (class `btn btn-danger`; sets `confirmZero` and runs the save again). Any edit to the budget input clears `confirmZero`. `renderConfirm` in shared.js:237-246 has a fixed `Delete` label, so build this box with `actionButton` and `element` from shared.js instead of changing it. After a successful save set `confirmZero` back to false.
- CSS: `.plan-unsaved` colour `var(--muted)`, weight 600 (the marker must also be readable without colour: the words carry it).

Tests, new `test/planFormState.test.js` (import both helpers from `../src/views/settings/plan.js`): `planDraftDirty` with an all-null draft (false), a draft without the income key (false), budget `'1000'` against 100000 cents (false), `'1000.50'` (true), `''` against saved 100000 (true), income changed only (true); `needsZeroBudgetConfirm(100000, 0)` true, `(0, 0)` false, `(100000, 100)` false, `(0, 500)` false.
