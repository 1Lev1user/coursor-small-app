## Goal
CSV and Excel files with a separate fee per row (Revolut-style `Fee` column) no longer lose the fee: an exchange of -100.00 with a fee of 1.50 is imported as an expense of 101.50. The Columns step gets an optional "Fee" column. Today the fee column is dropped and the money out is understated.

## Notes
Source: D-bank.md problem 3 (VERIFIED on an ASSUMED shape, probe p03_csv2.mjs B7: "-10000 (fee lost)"), NOT among the 8 claims re-checked in D-bank-verify.md, so there is no independent confirmation; it rests on one probe of an assumed shape. Whether the bank's Amount already contains the Fee is UNVERIFIED: verify with the owner's sample file (the Balance column of the sample can settle it: previous balance + amount - fee = next balance if Amount excludes the fee). Adding the fee to an amount that already includes it would double count; this is why the owner must check the Check panel (C-057) totals against the bank's.

Design:
- New optional column key `fee`. `guessColumns` (text.js:336-489): category with keywords `fee`, `komisija`, `komisijas maksa`, `комиссия`, matched only when the header equals one of them after normalisation (`normalizedHeader[i] === keyword`) so that "Fee type" or "Free text" are not caught; set `columns.fee` only when found (do NOT add it to `emptyColumns()`: the deepEqual at importText.test.js:288 would fail).
- `rowsToStatement` (text.js:766-870): when `columns.fee >= 0`, the fee cell parses with `parseAmountWith` and is non-zero, and the row's currency is EUR, add `Math.abs(fee)` to `amountCents` for rows whose direction is 'out'. Rows of direction 'in' and rows in a foreign currency keep their amount unchanged in this card (fee semantics for them are unverified); say so in the hint text.
- Columns step (import.js:860-881): `columnSelect(ctx, 'fee', 'Fee (optional)', true, 'Added to the amount of money out. Leave empty if the amount already includes the fee.')` after Bank reference; add `fee: -1` to the UI copy in startTable (import.js:563).
- Saved layouts: a guessed `fee` column is NOT inherited by an already saved layout (it would silently change amounts of an import that was confirmed before). Extend `mergeSavedColumns(guessedColumns, savedColumns)` (added by C-064 for the saved-layout merge at import.js:584) so that `fee` always comes from the saved columns (or -1), and add a test for that.

Regression tests (new file, synthetic; `parseDelimited` -> `findHeaderRow` -> `guessColumns` -> `rowsToStatement`):
1. The failing input from the research (assumed Revolut shape, header `Type,Product,Started Date,Completed Date,Description,Amount,Fee,Currency,State,Balance`): `EXCHANGE,Current,2026-09-18 09:00:00,2026-09-18 09:00:00,Exchanged to USD,-100.00,1.50,EUR,COMPLETED,886.00`. EXPECTED: guessColumns finds `fee` at index 6; the row is 'out' with amountCents 10150. ACTUAL before: 10000.
2. Fee `0.00` and empty fee leave the amount unchanged (`CARD_PAYMENT ... -20.00,0.00 ...` stays 2000).
3. An 'in' row with a fee (`TOPUP,...,500.00,1.00,EUR,...`) stays 50000.
4. A foreign-currency row (`-50.00` USD with fee `0.50`) keeps `originalAmountCents` 5000 and `amountCents` null.
5. Header "Fee type" or "Free text" is not taken as the fee column; a file without a Fee header has no `fee` key in the guessed columns (existing deepEqual stays green).
6. Comma-decimal file (`Datums;Apraksts;Summa;Komisija`, `13.09.2026;Valūtas maiņa;-100,00;1,50`) gives 10150 out.
