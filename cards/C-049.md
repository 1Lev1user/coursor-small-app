## Goal
The Search panel in Month shows the sum of all matching entries next to the result count, so "how much did I spend on groceries since July" no longer needs a calculator.

## Acceptance
- `node --test test/searchTotals.test.js` exits 0
- `node --test test/search.test.js` exits 0
- `npm test` exits 0
- Manual (design-review): Search with a text filter that matches expenses only, incomes only and both, at 390, 768 and 1280 px, light and dark; the count-and-total line wraps without overflow; owner checks
- Manual (owner): search "rimi" over Jul-Oct; the line reads the count and the spent total; the total covers all results even when the list shows only the newest 100

## Do not touch
- SCHEMA_VERSION and MIGRATIONS
- `searchEntries` behaviour (test/search.test.js stays green unchanged) and the 100-result cap (`RESULT_LIMIT`)
- Month entries list, Month CSV
- existing test files
- Limit for `src/search.js`: one new pure exported function, `searchTotals`.

## Notes
Source: C2 4.1 and 6.3 ("Search ... works well and is fast. BUT: no total / sum of the results, so 'how much on X' needs a calculator"; screenshot c2-56-phone-search-rimi-3m.png); A gap 19. Line numbers are from `main-work` at 05d1355; verify before editing.

`src/search.js`: add `export function searchTotals(results)` where `results` is the array `searchEntries` returns (`{ type, entry }`). Return `{ expenseCount, incomeCount, expenseCents, incomeCents }`. Expense cents use `spendCents(entry)` from `./budget.js` (a refund counts negative, src/budget.js:18-21); income cents use `entry.amountCents`. It sums every result, not only the first 100.
`src/views/searchPanel.js` `update()` (:243-262): after `count.textContent = resultCountText(results.length)` append the totals text built by a small exported `searchSummaryText(results)` (in the same file): `<count>` alone for zero results; otherwise `<count> · Spent €X` when only expenses match, `<count> · Income €Y` when only incomes match, `<count> · Spent €X · Income €Y` when both (amounts with `formatEuro`). The element already is a `role="status"` live region (:238-239), so screen readers hear the total. When `results.length > RESULT_LIMIT` the existing note (`Showing the newest 100. Narrow the search to see more.`) stays; the totals still cover all results, and the note already tells the user that only the list is capped.
The unfiltered Month entries list below the results (C2 4.1) is not changed here.

Tests, new `test/searchTotals.test.js` (import `searchEntries`, `searchTotals` from `../src/search.js`, `defaultData` from `../src/model.js`, `searchSummaryText` from `../src/views/searchPanel.js`): two expenses (1000 and 250 cents) and one refund (300 cents) matching one text give `expenseCents` 950 and `expenseCount` 3; one income of 500 gives `incomeCents` 500; zero results give all zeros; 150 matching expenses of 100 cents each give `expenseCents` 15000 (not 10000); `searchSummaryText` for the expense-only, income-only, both and empty cases uses `formatEuro` for the amounts (assert with the same call).
