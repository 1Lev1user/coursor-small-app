## Goal
A Swedbank Latvia/Estonia/Lithuania statement export has a record-type column ("Ieraksta tips", "Reatüüp", or an empty header in LT): 10 = opening balance, 20 = transaction, 82 = turnover, 86 = closing balance, 900 = unknown (research/3.1/bank-shapes.md, READ in three open tools). Today only some of these lines are caught as balance lines by their text. After this card, when a column holds only these codes, every row whose code is not 20 is skipped as a summary row, whatever its text says.

## Notes
- Detection, either:
  - the header normalises to 'ieraksta tips', 'reatuup', 'kirje tuup' or 'record type'; or
  - an unnamed column whose samples are all in {10, 20, 82, 86, 900} and at least one is 20.
- Skip reason: 'summary row'.
- Swedbank LV header (12 columns, READ): `Klienta konts;Ieraksta tips;Datums;Saņēmējs/Maksātājs;Informācija saņēmējam;Summa;Valūta;Debets/Kredīts;Arhīva kods;Maksājuma veids;Refernces numurs;Dokumenta numurs`. Amount unsigned with comma decimals, `D`/`K`, dates `DD.MM.YYYY`, `;`.
- Tests (made-up rows): a file with 10, 20, 20, 82, 86 rows, two currencies (10/86 repeated per currency) and a 900 row. Expected: only the 20 rows are imported, with directions from D/K, and money in/out equal the sums of the 20 rows. Also: the EE header variant; the LT variant with an empty header cell; a file without such a column is unchanged.
