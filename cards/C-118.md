## Goal
Today a row is sorted only by a saved rule (the "Remember" tick) or by the card's MCC. If you once put NARVESEN into a category without ticking Remember, the next import asks again. After this card, a row with no saved rule takes the category of the latest imported entry with the same shop keyword, shown as a suggestion ("From earlier imports"), never saved as a rule unless you tick Remember. Existing imported entries count from the first import after the update (warm start), with nothing written to the data.

## Notes
- Order in `defaultDecisions`: saved rule, then history suggestion, then MCC suggestion, then defaults (planner checks this against C-066/C-098 eligibility: a history-suggested row is not "ruled", so pairing still applies unless the planner finds a reason not to).
- Keyword: the same `extractPattern` used for rules, compared with the same whole-word matcher (C-099). Source entries: expenses and incomes with an `importId` and a `bankText`; the latest by date wins; a refund keeps its refund flag; transfers and skipped rows are not sources.
- Only the category (and subcategory / income category) is suggested; amounts never.
- The row shows a small label "From earlier imports" (text through textContent); Known stays for saved rules only.
- Performance: build the keyword index once per import (data can hold thousands of entries).
- Tests: a match from an earlier import; latest wins; no match; a saved rule beats history; history beats MCC; stop words and short keywords never match; nothing is written to data.rules.
- Amendment (card-planner check at e14cabb, 2026-10-18):
  - The decision gets `suggestion: { source: 'history', kind, categoryId, subcategoryId, incomeCategoryId }` only when a history suggestion is applied (no key otherwise), because importMcc and importOwnTransfer tests deepEqual whole decisions.
  - Stored-entry keyword = `extractPattern` of the first segment of `bankText` split on ' · '. A row matches it with the C-099 whole-word matcher on counterparty and description. Longest keyword wins, then the latest `entry.date`, then the later list position. Money out uses non-refund expense entries; money in uses refund and income entries. No shop-expense-to-refund fallback.
  - Entries in Uncategorised or in a deleted category, subcategory or income category are not sources.
  - The label "From earlier imports" shows only while the row's kind and categories still equal `suggestion`, so editing, Apply to all, pairing to Transfer or the salary guess hide it. Reuse existing classes; no CSS change.
  - Limit for `src/views/import.js`: a pure exported `suggestionLabel(decision)` and its one use in renderDecisionRow.
- Amendment after the worker's real-file check (2026-10-18): a history suggestion is applied (and the `suggestion` key set) only when it changes the row's choice, that is when its kind and categories differ from what the row gets without it (the MCC suggestion or the default). Otherwise the row is as before and carries no label, so income left in the default "Other" or expenses whose MCC already gives the same category do not show "From earlier imports".
- Amendment after review (2026-10-18): matching is exact, not by substring. A stored keyword matches a row only when it equals the row's own `extractPattern` of the counterparty (then of the description, if the counterparty gives none). This replaces "longest keyword wins": on the owner's file a mall name inside other shops' card text ("ORIGO") matched a cafe entry and moved Rimi rows to the wrong category. Between several entries with the same keyword the latest `entry.date` wins, then the later list position. History does not apply when the row's kind comes from a reversal, a bank type hint or a skip.
