## Goal
A goal closed by mistake (or one the user wants to keep saving for) can be reopened from the Closed goals list, with its saved money intact.

## Acceptance
- `node --test test/goalReopen.test.js` exits 0
- `node --test test/goals.test.js` exits 0
- `npm test` exits 0
- Manual (design-review): Settings > Goals > Closed goals with a Reopen and a Delete button, at 390, 768 and 1280 px, light and dark; tap targets at least 44 px (after C-072 the buttons may be small chips with a 44 px tap area); owner checks
- Manual (owner): close a goal that has money, open Closed goals, tap Reopen: the goal is back in the open list with the same saved amount and progress, and can again be the Home goal card

## Do not touch
- SCHEMA_VERSION and MIGRATIONS (`closedAt: ''` already means open)
- `closeGoal`, `deleteGoal`, `contribute`, `goalProgress` behaviour
- Withdrawing money from a goal (not part of this card)
- existing test files (test/goals.test.js stays green unchanged)

## Notes
Source: C2 3.4 ("goal moves to a collapsed 'Closed goals (1)' section (c2-50) which offers only Delete; missing: reopen / withdraw money from a goal", screenshot c2-47-phone-goal-close-confirm.png). Line numbers were re-checked on `main-work` at 6788db8; verify before editing. The Reopen button sits in the "Goals" group of Settings (C-041). Reopening changes no money figure: contributions stay expenses in Savings, and whether they leave "Money now" is decided by the money cards (decision 1), not here.

`src/goals.js`: add `export function reopenGoal(data, id)` after `closeGoal` (:95-104): find the goal with `ensureGoals(data)`; unknown id returns `{ ok: false, reason: 'Goal does not exist.' }`; a goal with `closedAt === ''` returns `{ ok: false, reason: 'Goal is already open.' }`; otherwise set `goal.closedAt = ''` and return `{ ok: true, goal }`. Nothing else changes: contributions stay expenses in Savings with their `goalId`, so `goalProgress` is identical before and after.
`src/views/settings/goals.js` `renderClosedGoal` (:366-384): the action row (`actions.append(goalAction(ctx, goal, 'delete', ...))`, :376) gets a first button `Reopen` (`btn`, built with `actionButton` and id `goal-action-reopen-<goal id>`). Reopening is not destructive, so there is no confirmation: the click calls `reopenGoal(ctx.data, goal.id)` and `finish(ctx, 'Goal reopened', 'goals-title')` (`finish`, :143-151, saves, sets focus and toasts). On `ok: false` show nothing different from the unknown-goal path: `finish` still re-renders. Import `reopenGoal` next to `closeGoal` (:3).

Tests, new `test/goalReopen.test.js` (import `addGoal`, `closeGoal`, `reopenGoal`, `contribute`, `goalProgress` from `../src/goals.js`, `defaultData` from `../src/model.js`; fixed dates, same style as test/goals.test.js:51-60 and :86-114): close then reopen sets `closedAt` back to `''`; reopening a goal that is open returns `ok: false` with `Goal is already open.`; an unknown id returns `Goal does not exist.`; after `contribute(...)` 5000 cents, close and reopen, `goalProgress(data, id).savedCents` is still 5000 and the expense still carries the `goalId`.
