## Goal
"Replace everything" from a backup follows the owner's order (decision 18): first a preview of the chosen file (dates and entry counts, next to what the device has), then a download of the current data, then the replacement. The exported file also carries its own backup date, so the "No backup yet" warning does not come back after a restore.

Root cause of the date: `doExportBackup` (src/views/settings/backup.js:61-68) serialises the data first and sets `lastBackupISO = todayISO()` afterwards, so the file always holds the previous value.

`src/backup.js`, three small pure exports:
- `markBackedUp(data, now = new Date())`: sets `data.settings.lastBackupISO = todayISO(now)` and returns the previous value (`null` when absent).
- `describeBackup(data)`: `{ expenses, incomes, subscriptions, firstDate, lastDate }`, counts from the arrays and the earliest and latest `date` over expenses and incomes (empty strings when there are no entries). Dates are `YYYY-MM-DD` strings, compared as strings.
- `restoredLastBackup(incomingISO, todayISO)`: the incoming value when it is a non-empty string, otherwise `todayISO` (the restored data equals a file the user holds; a file exported before this change has no date).
`src/views/settings/backup.js`:
- `doExportBackup`: `const previous = markBackedUp(ctx.data)` before `exportBackup`; download; `if (!persist(ctx))` put `previous` back and `ctx.render()`. Toast text unchanged.
- `beginImportBackup` (:77-107): also store `state.pendingImportIncoming = describeBackup(preview.data)` next to `pendingImportCounts` (add the field to shared.js `state` and reset it where `pendingImportCounts` is reset: :89, :102, :118, :126, :242 and `closeTransientUi`, shared.js:63).
- Choice box (:213-249): add a first line `This file: 81 expenses, 2 incomes, 1 subscription · 2 Jun 2026 to 3 Oct 2026` (use `fullDate` from `../../months.js`; omit the dates when the file has no entries) above the existing text, and keep `Your N expenses and M incomes stay` / `... are deleted`. The Everything paragraph ends `Your current data is downloaded first, then replaced. This cannot be undone.` The red `Replace everything` button is already inside this confirm box (decision 26: red only inside a confirm step).
- `confirmImportBackup(ctx, 'all')` (:109-131): when the device has any expense, income or subscription, download the current data before replacing it: `downloadText(\`my-expenses-before-replace-${todayISO()}.json\`, JSON.stringify(ctx.data, null, 2), 'application/json')`, the same approach as `restorePreUpdate` (:138-157). Skip the download when the device is empty. After building `next`, set `next.settings.lastBackupISO = restoredLastBackup(next.settings.lastBackupISO, todayISO())` for mode `all` only. If `persist` fails, put the previous data back with `replaceAppData` (copy taken as in :147-148) and `ctx.render()`.
- Unverified: a browser may ask permission for a download or block it silently; here only one file is downloaded per restore and the replacement follows at once, as `restorePreUpdate` does. The download is the safety copy the owner chose (decision 18); no hidden copy is kept in localStorage. If the owner wants a second confirmation between the download and the replacement, that is a small follow-up card.

Tests, new `test/backupRestoreSafety.test.js`: `markBackedUp` sets today (fixed `new Date(2026, 9, 4)` gives `'2026-10-04'`) and returns the previous value, including `null`; an export made after `markBackedUp` round-trips: `importBackup(exportBackup(data).json).data.settings.lastBackupISO === '2026-10-04'`; `describeBackup` on a crafted `defaultData()` with three expenses and one income gives the counts and the earliest and latest date, and on an empty one empty dates; `restoredLastBackup('2026-09-01', '2026-10-04')` is `'2026-09-01'`, `(null, ...)` and `('', ...)` give today.
