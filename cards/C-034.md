## Goal
A new owner sets income and payday in Setup and starts on payday counting; every sentence about salary, usual income and subscriptions says what the app really does; the bank-import salary hint matches the new rule.

## Acceptance
- `node --test test/incomeWording.test.js` exits 0
- `node --test test/incomeWording.test.js 2>&1 | grep -E '^# pass ([5-9]|[1-9][0-9])'` exits 0
- `grep -c "added for you" src/views/add.js` prints 0
- `grep -c "payday" src/views/setup.js` prints 1 or more
- `npm test` exits 0
- Manual (design-review): Setup with the new Payday field, filled and with an error, at 390, 768 and 1280 px, light and dark; Home note line; owner checks
- Manual (owner): fresh profile, Setup with income 2,000 and payday 25: Home opens with no review card for last month; Settings > Regular income lists "Salary EUR 2,000.00 · day 25"; Month shows income 0 until payday
- Manual (owner): data from 2.0 (old rule): Plan still has the Usual monthly income field and it still works

- SCHEMA_VERSION and MIGRATIONS
- the logic of Add income, the import wizard and the charts; strings and the one `suggestSalary` function only
- style.css
- existing test files (test/importUi.test.js:184-195 tests `suggestSalary` and must pass unchanged)
- Limit for `src/views/add.js`: the Home note (lines 683-687) and the income form note (lines 726-731); export two small text helpers, nothing else.
- Limit for `src/views/import.js`: `suggestSalary` (lines 143-161) and the hint at lines 1136-1145 only.

- Limit for `src/views/chartView.js` and `src/views/year.js`: the four strings named below only.

## Notes
Why: Setup (setup.js:244) writes only `usualMonthlyIncomeCents`, so a new owner would be on the old rule forever, and the app tells him three different things about salary. Bugs from testing: Home says "Salary and subscriptions are added for you." (add.js:683-687) but subscriptions only remind (settings/subscriptions.js:372-373) and salary is never an entry; Setup and Plan say "usual monthly income is counted automatically"; the review card for a month the owner never had shows right after Setup because nothing records when he started (needs `trackingStartMonth`).

Setup (src/views/setup.js):
- `draft` (setup.js:8-14) gets `payday: ''` and it is reset with the others after a successful save (:253-259). After the income field (:335-346) add a field 'Payday (day of month)' (`inputMode` numeric, placeholder '25'), helper 'The day your income usually arrives. It counts on that day.'
- `submitSetup` (:169-262): in addition to what it does now, set `ctx.data.settings.trackingStartMonth = currentMonthKey()` (import from months.js). When `incomeCents > 0`: call `validateIncomeSource(ctx.data, { name: 'Salary', amount: draft.income, dayOfMonth: draft.payday, weekendRule: 'keep', incomeCategoryId: 'salary' })` and `addIncomeSource(ctx.data, result.value, new Date())` (C-030); a failure on field 'day' sets the error on the payday field ('Enter a day from 1 to 31.') and focuses it, before anything is written. When `incomeCents === 0` no source is created and the payday field is ignored. Then set `settings.usualMonthlyIncomeCents = 0` (the source now holds the number; one truth). Keep `refreshCurrentMonthPlan` (:250).
- Replace the sentence at :362-366 with 'Your income counts on its payday, when you confirm the real amount. You can add more regular incomes later in Settings.'

Plan (src/views/settings/plan.js): show the 'Usual monthly income (EUR)' input (:158-168) and keep saving it (:99-111) only while `ctx.data.settings.incomeSourcesFrom === ''`. Otherwise replace the input by a read-only line 'Income: set under Regular income (Settings > Paydays).' and skip the income parsing in `savePlan`. Replace the note (:191-196) by: old rule 'Usual monthly income is counted automatically from the 1st of each month. Add it under Regular income to count it on payday.'; new rule 'Income is counted on its payday under Regular income.'

Home (src/views/add.js): export `homeAutoNote(data)` and use it at :683-687: old rule (`incomeSourcesFrom === ''`) 'Your usual income is counted automatically. Subscriptions only remind you. Everything stays on this device.'; otherwise 'Paydays and subscriptions remind you when they are due. Nothing is added until you confirm it. Everything stays on this device.' Export `incomeFormNote(data)` for the Add income form note (:726-731) and for the same sentence in income.js:406 (duplicate text; income.js may inline the same two strings): old rule unchanged text; new rule 'Regular income arrives through its payday reminder. Use this form for one-off income such as a bonus or a gift.'

Charts and year (strings only, make them depend on `data.settings.incomeSourcesFrom === ''` the same way):
- chartView.js:166 'Usual salary from Plan plus extra income you logged. This raises Cash left, not the spend budget.' stays for the old rule; new rule 'Income you received, by category. This raises Cash left, not the spend budget.'
- chartView.js:174 empty text: new rule `No income for ${monthLabel(ctx.monthKey)}. Add your regular income in Settings > Paydays or add income from Home.`
- chartView.js:63-64 'from Settings → Plan' only appears for the plan row, which no longer exists on payday months; leave it.
- year.js:141 'Income includes usual salary from Plan. Difference is income minus spent.': new rule 'Income is what you received each month. Months before payday counting started include your usual salary from Plan. Difference is income minus spent.'

Import (src/views/import.js): `suggestSalary` (:148-161) currently compares money in with `settings.usualMonthlyIncomeCents` within 15%. Keep that (old rule, the test at test/importUi.test.js:184-195 must pass) and additionally accept a match against any active source with `incomeCategoryId === 'salary'` (`Math.abs(row.amountCents - source.expectedCents) <= source.expectedCents * 0.15`). The hint at :1136-1145 'Imported salary replaces your usual income (...) for that month.' stays for months on the old rule; for a month where `usesIncomeSources(ctx.data, monthKeyOf(row.date))` it reads 'Counts as the salary for that month; it is not added on top of your regular income.' (`row.date` is the row's ISO date; verify the field name in the row object at the top of the row renderer before editing.)

test/incomeWording.test.js (new) asserts: `homeAutoNote` for old and new rule (and that neither contains "added for you"); `incomeFormNote` both rules; `suggestSalary` returns Salary for 2,050.00 when an active salary source expects 2,000.00 and `usualMonthlyIncomeCents` is 0, and {} for 3,000.00; the Setup helper path is covered by C-030's tests, so here assert only that `validateIncomeSource` rejects day '32' with field 'day' (guards the wiring).

Unverified: whether the row object in import.js uses `row.date` (the tests in test/importUi.test.js build rows with a date as first argument, so it is very likely).
